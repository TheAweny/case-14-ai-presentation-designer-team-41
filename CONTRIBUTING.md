# Как участвовать

Спасибо за интерес к проекту. Ниже — минимум, которого достаточно, чтобы ваш патч прошёл ревью.

## Окружение

```bash
corepack enable
yarn install
uv sync
```

Нужны Node 22.13+ и Python 3.12 (uv поставит его сам). Пакетный менеджер для TypeScript —
только yarn, для Python — только uv.

## Перед пушем

```bash
yarn lint && yarn typecheck && yarn test
yarn lint:py && yarn typecheck:py && yarn test:py
yarn boundaries:py
yarn codegen && git diff --exit-code
uv run write-golden-ir --check
```

Хуки `lefthook` линтят только изменённые файлы, полный набор гоняет CI.

Сквозные проверки редактора в браузере — `yarn nx run web:e2e` (Playwright: фокус, черновик в
IndexedDB, показ, узкий экран). Сервер разработки они поднимают сами; нужен Chromium той же
ревизии, что и `@playwright/test` (`PLAYWRIGHT_BROWSERS_PATH`, если браузеры лежат не в кеше).

## Правила, о которых спрашивают чаще всего

- **Границы слоёв.** В Python-движке нет ни одного вызова модели, в TypeScript нет работы
  с `.pptx`. Слои движка не импортируют друг друга. Правила закреплены в `import-linter` и
  `@nx/enforce-module-boundaries`; отключать их, чтобы «прошло», нельзя.
- **Никакой заточки под шаблон.** Ни условий вида «если шаблон такой-то», ни зашитых названий
  макетов, цветов, шрифтов и координат. Всё, что зависит от шаблона, берётся из профиля шаблона.
- **Контракты.** Источник правды — Zod-схемы в `packages/contracts`. Pydantic-модели движка
  генерируются; править сгенерированные файлы руками нельзя. После правки схем запустите
  `yarn codegen` и закоммитьте результат одним коммитом со схемами.
- **Промпты.** Инструкции агентов лежат в `registry/agents/<id>/instructions.md`, в коде
  промптов быть не должно. Поменяли смысл инструкции — поднимите версию в `agent.yaml` по semver.
- **Тесты.** Каждая новая проверка аудита приходит с двумя тестами: слайд, который её нарушает,
  и слайд, который ей соответствует. Тесты пайплайна работают с фейковым провайдером моделей,
  без GPU и без сети.
- **Фикстуры контрактов.** `packages/contracts/fixtures` читают обе стороны: vitest гоняет их
  через Zod, pytest — через сгенерированные Pydantic-модели. Новый контракт приходит с
  валидным и невалидным случаем, у невалидного указано, где именно он должен упасть.
- **Генерируемые файлы.** `docs/AUDIT.md` и `docs/LICENSES.md` собираются утилитами из `tools`,
  golden-фикстуры — командой `uv run write-golden-ir`; руками их не правим.

## Грабли

Короткий список того, на чём спотыкаются, и почему так сделано. Здесь же живут причины
версионных пинов — в `docs/DECISIONS.md` их нет, туда идут только архитектурные решения.

- **`corepack enable` падает с `EPERM` на Windows.** Шимы пишутся в каталог Node внутри Program
  Files, на это нужны права администратора. Три выхода: один раз запустить терминал от админа;
  поставить шимы в свою папку через `corepack enable --install-directory` и добавить её в `PATH`;
  либо ничего не настраивать и писать `corepack yarn ...` вместо `yarn ...`.
- **Локальный `mastra.db` остаётся занят после LibSQL `close()` на Windows.** Нативный драйвер
  LibSQL удерживает файловые дескрипторы подготовленных выражений до сборки мусора. Для `file:`
  фабрика Mastra передаёт адаптер `NodeSqliteClient` на встроенном `node:sqlite` (Node 22.13+),
  который освобождает базу при `close()`. Удалённый LibSQL использует прежний драйвер. Каждый
  прогон вызывает `closeMastra` в `finally`; ошибки очистки не подавляются. Адаптер использует
  публичный интерфейс `SqliteClient` из Mastra и не требует дополнительных зависимостей.
- **`yarn -v` показывает 1.22.** Не включён corepack, см. пункт выше.
- **Импорты с расширением `.js`.** Пишем `import { x } from './foo.js'` для файла `foo.ts`.
  Причина — в комментарии в `tsconfig.base.json`.
- **TypeScript закреплён на 6.0.3, не обновлять до 7.x.** `typescript-eslint` заявляет поддержку
  `<6.1.0`, а `@nestjs/schematics` требует `>=6.0.0`; пересечение — только ветка 6.0.x. Перейдём,
  когда `typescript-eslint` объявит поддержку семёрки, отдельным коммитом.
- **`@mastra/*` стоят точными версиями, без `^` и `~`.** Пакеты Mastra версионируются независимо
  друг от друга, и любое расхождение между `@mastra/core` и `@mastra/libsql` ловится только на
  сборке. Обновляем осознанно и одним коммитом. Бета-функции Mastra (file-based agents, Editor)
  не используем.
- **Yarn отказывается ставить свежую версию пакета.** Это карантин на только что опубликованные
  релизы, защита от компрометации цепочки поставки. Не отключаем — берём версию постарше.
- **Конфликт в `yarn.lock` или `uv.lock`.** Не мержим руками: берём версию из `main` и ставим
  зависимости заново.
- **Конфликт в сгенерированных файлах** (`packages/contracts/schema`, `_generated.py`).
  Разрешается перегенерацией, а не редактированием: взять версию из `main` и запустить
  `yarn codegen`.
- **Файл `project.json` нельзя называть так вне конфигов Nx.** Nx считает любую папку с ним
  отдельным проектом, и импорты из неё ломают `@nx/enforce-module-boundaries`. Поэтому словарь
  страницы проекта лежит в `project-page.json`.
- **`swagger-ui-dist` в вебе закреплён на той же версии, что тянет `@nestjs/swagger`.** Иначе в
  `node_modules` две копии Swagger UI по полтора мегабайта. Обновляем вместе. Он же приносит
  `@scarf/scarf`, который при установке шлёт статистику; `scarfSettings.enabled: false` в
  корневом `package.json` это выключает.

## Лицензии зависимостей

Решение открытое, поэтому новая зависимость допустима только под MIT, Apache-2.0, BSD, ISC или
MPL. GPL и AGPL не подходят: заказчик берёт решение в пилот и внедрение. Проверка:

```bash
yarn licenses
```

Задача пересобирает `docs/LICENSES.md` и падает, если в дереве появился копилефт.

Отдельно про шрифты: в образы кладём только свободные шрифты, а шрифты пользовательского
шаблона достаём из самого файла во время работы. Коммитить чужие корпоративные шрифты нельзя.

## Git

Короткие ветки от `main`, коммиты в стиле conventional commits. Датасет организаторов, содержимое
`runs/` и `.env` в репозиторий не попадают.

В `docs/DECISIONS.md` пишем, только если решение нельзя вывести из кода за минуту и его отмена
затронет больше одного пакета. Выбор библиотеки, версия зависимости, настройка инструмента — не
туда: им место в комментарии рядом с самой настройкой или в разделе «Грабли» выше. Записи в
журнале не редактируем, решение изменилось — добавляем новую со ссылкой на старую.
