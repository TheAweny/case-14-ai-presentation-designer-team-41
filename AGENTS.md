# AGENTS.md

Правила работы в этом репозитории. Проект — сервис генерации презентаций по загруженному шаблону (хакатон ЛЦТ-26, кейс VK Tech).

## Общение

- Отвечай по-русски. Идентификаторы, имена файлов и коммиты — по-английски.
- Перед изменениями в незнакомой части репозитория сначала прочитай `docs/ARCHITECTURE.md`.

## Стек и инструменты

- Пакетный менеджер для TypeScript — **только yarn**. Никогда не используй npm и pnpm.
- Пакетный менеджер для Python — **только uv**. Никаких pip, poetry и venv вручную.
- Node 22.13+, Python 3.12.
- Задачи запускаются через Nx: линт, типы, тесты, сборка, кодогенерация.
- Все пакеты `@mastra/*` держим на одной точной версии. Обновляем только осознанно, отдельным коммитом.
- Бета-функции Mastra (file-based agents, Editor) не используем.

## Границы слоёв

Главное правило репозитория: **в Python-движке нет ни одного вызова модели, а в TypeScript нет работы с .pptx.**

- **TypeScript** — интерфейс, API, оркестрация, все обращения к моделям, контекстные (смысловые) проверки аудита.
- **Python (`engine/`)** — разбор шаблона, вёрстка, графики и таблицы, экспорт, рендер, детерминированные проверки аудита.

Внутри движка слои `parser`, `layout`, `visuals`, `export`, `render`, `checks` **не импортируют друг друга**. Соединяет их только API движка. Правила закреплены в import-linter, в TypeScript — в `@nx/enforce-module-boundaries`. Если правило мешает, это повод обсудить архитектуру, а не отключить проверку.

Слой вёрстки детерминирован. Если текст не влезает, он возвращает сигнал о переполнении, а переписывание текста делает агент на стороне TypeScript.

## Контракты

- Источник правды — Zod-схемы в `packages/contracts`. Pydantic-модели движка **генерируются** из них.
- Менять сгенерированные файлы руками нельзя. После правки схем запускай кодогенерацию и коммить результат.
- На границе TypeScript и Python ответы движка валидируются схемами.

## Промпты и агенты

- Промпты и конфиги агентов лежат в `registry/agents/<id>/` отдельными файлами. **В коде промптов быть не должно** — это требование ТЗ.
- У каждого агента есть версия по semver. Меняешь смысл инструкции — поднимай версию.
- Каждый прогон записывает манифест: версии агентов и промптов, модели с ревизиями, seed.

## Что запрещено предметно

- **Хардкодить под конкретный шаблон.** Никаких условий вида «если шаблон такой-то», никаких зашитых названий макетов, цветов, шрифтов и координат. На защите дадут незнакомый шаблон, и решение обязано работать на нём. Всё, что зависит от шаблона, берётся из профиля шаблона.
- Отключать проверки границ, типов или линта, чтобы «прошло».
- Оставлять в коде и документации `TODO`, `XXX`, `lorem ipsum`, «вставьте текст» — наш же аудит ищет эти строки.
- Коммитить датасет организаторов, содержимое `runs/` и `.env`.

## Тесты

- Каждая новая проверка аудита сопровождается двумя тестами: слайд, который её нарушает, и слайд, который ей соответствует.
- Тесты пайплайна работают с фейковым провайдером моделей и записанными ответами — они должны проходить без GPU и без сети.
- Файл `docs/AUDIT.md` генерируется из реестра проверок, руками его не правим.

## Производительность

Бюджет на колоду — 5 минут. План колоды строится один раз и переиспользуется всеми тремя вариантами вёрстки. Обращения к моделям по слайдам идут параллельно. Профиль шаблона кешируется при импорте.

## Git

- Работаем короткими ветками от основной, коммиты в стиле conventional commits.
- Сгенерированные файлы коммитим вместе с изменением схем, одним коммитом.
- В `docs/DECISIONS.md` пишем, только если решение нельзя вывести из кода за минуту и его отмена затронет больше одного пакета. Версии зависимостей, выбор библиотек и настройки инструментов — не туда: им место в комментарии рядом с настройкой или в разделе «Грабли» в `CONTRIBUTING.md`.
