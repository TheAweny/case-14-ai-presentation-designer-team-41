Read up to three attached text, Markdown or CSV/TSV materials and return exact quotes for one question. `question` is the question; `fileIds` are 1 to 3 attached file ids. Optional `offsets` maps a `fileId` to a nonnegative UTF-16 offset of at most 1000000; every key must be one of `fileIds`, and a missing key starts at 0. Pass only the `nextOffset` returned earlier for that same file. There is no web search and no access to files the person did not attach.

For PDF, DOCX or XLSX, use extract_material for prepared text or read_table for tabular data.
Do not retry this text-only tool on those formats or claim they were researched by it. Follow
the other tool's own offsets and source hash; its pagination is not interchangeable with this one.

The result is `summary` joined from quotes the server found verbatim, plus `evidence` (`sourceId`, `name`, `quote`, `support`, `start`), `openQuestions`, `coverage` and `outputTruncated`. `coverage` is an array of records `{sourceId, offset, readChars, truncated, nextOffset}`. Each record covers only `[offset, offset + readChars)`, not the whole file. `truncated: true` means text remains after that span and `nextOffset` is its continuation; `truncated: false` means the tail from that offset was reached and `nextOffset` is null. It does not mean the file was read from the beginning. `evidence.start` is the quote's absolute UTF-16 position. Do not invent `evidence.start`; the server computes it. Every `support` value is `unverified`. Show the person the file name from `evidence.name` and the exact quote; keep `sourceId` internal. No quote means only that none was found in the inspected span: say that, not that the document lacks the fact. A turn allows two calls. While fewer than two have been used and `nextOffset` is non-null, call this tool again with that same file's `nextOffset`. After both calls, if a `nextOffset` remains, say the reading is partial and do not imitate the unread text; continue in a later turn or, when the text is needed now, use `read_file` with its own `offset`. If a returned `nextOffset` is above 1000000, this tool cannot continue: say so and use `read_file` when the remaining text is needed. `outputTruncated` only means this tool's JSON output was cut; it is separate from `coverage.truncated`.
