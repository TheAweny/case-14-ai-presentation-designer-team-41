Сервис собирает презентацию по загруженному шаблону `.pptx` и материалам. Шаблон читается как набор правил — палитра, шкала кеглей, сетка, макеты, — а не как готовые слайды с зашитым текстом. План колоды строится один раз, вёрстка раскладывает его в три варианта.

<Info>
  Скриншоты интерфейса в этот выпуск не входят: экраны ещё меняются. Ниже — карта понятий и то,
  какие статьи появятся следом.
</Info>

## Понятия

- **Проект** — папка колод, чатов и шаблонов одного аккаунта.
- **Шаблон** — файл `.pptx` или `.potx`. От его имени ничего не зависит.
- **Материалы** — текст и таблицы, из которых берётся содержание.
- **Режим** — чат, план или авто. Колоду собирают не все три.
- **Вариант** — одна из трёх вёрсток общего плана: `dense`, `balanced`, `airy`.
- **Аудит** — проверки геометрии, контраста и смысла. Часть из них видна в редакторе после правки.
- **Экспорт** — файл из того состояния слайда, которое открыто: `.pptx`, `.pdf`, PNG или HTML.

## Первая презентация

Пошаговый сценарий с экранами будет отдельной статьёй. Сейчас путь такой: войти в приложение, положить шаблон и материалы, описать задачу в поле на главной и выбрать режим. После сборки сравниваются три варианта, правки делаются в редакторе, файл забирается экспортом.

<Steps>
  <Step>
    Откройте приложение по ссылке «Приложение» в шапке. При сборке документации адрес задаётся
    переменной `NEXT_PUBLIC_APP_URL`, локально это `http://localhost:3000`.
  </Step>
  <Step>Загрузите свой шаблон. Незнакомый файл проходит тот же разбор, что и любой другой.</Step>
  <Step>
    Добавьте материалы и сформулируйте, для кого колода. Режимы ассистента описаны в
    [руководстве](/docs/guide/assistant/).
  </Step>
  <Step>
    Сравните варианты и откройте редактор. Если текст не влезает, вёрстка его не переписывает сама:
    она возвращает сигнал переполнения.
  </Step>
</Steps>

<Limitation>
  Ссылка «приложение» ведёт на адрес продукта, не на этот сайт. На `docs…` нет прокси `/api/backend`
  и нет сессии.
</Limitation>
