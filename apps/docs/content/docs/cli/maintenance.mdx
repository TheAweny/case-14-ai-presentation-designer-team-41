`lct backup` и `lct update` предназначены для Docker-установки на Linux/Ubuntu. Требуются
Docker Compose v2, GNU tar и уже запущенный PostgreSQL. Операции используют блокировку,
чтобы два обслуживания одной установки не выполнялись одновременно.

## Создать резервную копию

```bash title="terminal.sh"
lct backup
```

Команда временно останавливает работающие сервисы записи, создаёт дамп БД и архив, проверяет
его читаемость и возвращает ранее работавшие контейнеры в исходное состояние. На время создания
копии приложение будет недоступно. Изначально остановленные сервисы не запускаются.

Архив `backup.tar.gz` сохраняется **вне каталога установки**, в приватном каталоге
`~/.lct-backup-*`. Точный путь CLI выводит в конце операции. Права каталога — 0700, архива — 0600.

| Содержимое архива | Назначение                                                |
| ----------------- | --------------------------------------------------------- |
| `.env`            | Настройки, пароли и ключи шифрования установки            |
| `data/`           | Загруженные файлы и другие локальные данные приложения    |
| `runs/`           | Результаты и артефакты генераций                          |
| `database.sql`    | Дамп PostgreSQL                                           |
| `metadata.json`   | Commit, версии и состояние контейнеров при создании копии |

Внешние каталоги шрифтов, сертификаты прокси и кэш поиска не входят в копию. Исходники и
Docker-образы также не включены. Архив содержит секреты и пользовательские данные: храните
его с ограниченным доступом и переносите на отдельный носитель по вашей политике резервирования.

## Обновить приложение

```bash title="terminal.sh"
lct update
```

Либо выберите «Обновить сервис» в меню и подтвердите действие. Команда требует:

- чистое состояние Git, включая отсутствие неотслеживаемых файлов; игнорируемые `.env`, `data/`
  и `runs/` не мешают;
- ветку с настроенным upstream; detached HEAD не подходит;
- обновление fast-forward без расхождения веток;
- установленный Corepack и доступ к источнику кода и зависимостей.

Проверить состояние до обновления:

```bash title="terminal.sh"
cd /opt/lct26
git status --short
git branch -vv
lct status
```

Если установлена актуальная версия, команда завершится без создания копии. При наличии
обновления CLI сначала сохраняет резервную копию, затем обновляет код, устанавливает зависимости
через Yarn, собирает CLI и ранее работавшие сервисы. В конце проверяет их доступность.

Bootstrap `install.sh` не обновляет существующий репозиторий: повторный запуск установщика
не заменяет `lct update`. Отложенные изменения основной ветки сами по себе на сервер не попадают.

## Если обновление завершилось ошибкой

Сохраните путь резервной копии и команды, напечатанные CLI. Если изменение кода уже началось,
CLI выводит исходный commit и команды восстановления кода, сборки и запуска контейнеров.
Автоматического отката кода, миграций или данных нет. Возврат исходников на прежний commit
сам по себе не восстанавливает прежнее состояние БД.

```bash title="terminal.sh"
lct status
lct logs api
lct doctor
```

Для восстановления данных сначала распакуйте копию в **новый приватный каталог**, изучите
`metadata.json` и выберите совместимую версию PostgreSQL. Перед заменой сохраните текущее
состояние и остановите процессы записи. Восстанавливайте `.env`, `data/`, `runs/` и `database.sql`
согласованно: файл настроек содержит ключи к данным БД. Автоматической команды `lct restore`
пока нет; восстановление выполняется оператором через PostgreSQL и файловую систему.
