После первой установки настройки можно менять без повторного запуска `install.sh`. В главном
меню выберите «Модель и подключение» или «Настройки установки» либо выполните:

```bash title="terminal.sh"
lct model
lct configure
```

`lct model` меняет подключение модели; `lct configure` — адрес, порты, документацию API и поиск.
Мастер показывает итоговую сводку, просит сохранить настройки и предлагает применить их к сервису.
Существующий администратор и ключи шифрования сохраняются.

## Подключение модели

| Пункт мастера          | Какие данные подготовить                                      | Флаг провайдера        |
| ---------------------- | ------------------------------------------------------------- | ---------------------- |
| VK AI Space            | API-ключ и Project ID в формате UUID                          | `--provider vk`        |
| Yandex AI Studio       | API-ключ и ID каталога                                        | `--provider ai-studio` |
| OpenAI-совместимый API | Base URL с `/v1`, имя модели и при необходимости ключ         | `--provider openai`    |
| Тестовые ответы        | Данные подключения не нужны; генерация новых колод недоступна | `--provider offline`   |

CLI проверяет ответ модели перед сохранением. Если проверка не прошла, интерактивный мастер
предложит изменить подключение, сохранить его для дальнейшей настройки или завершить работу.
В режиме `--yes` неуспешная проверка завершает команду без сохранения новых настроек.
Доступные в вашей учётной записи модели и требования к ним описаны в [руководстве по моделям](/docs/cli/configuration/#подключение-модели).

Пример подключения собственного совместимого сервера:

```bash title="terminal.sh"
read -rsp 'API-ключ модели: ' LCT_MODEL_API_KEY; echo
export LCT_MODEL_API_KEY
lct model --yes --provider openai \
  --base-url http://127.0.0.1:8001/v1 --model my-served-model
unset LCT_MODEL_API_KEY
```

Адрес API должен быть доступен процессу CLI и приложению. Для приложения в Docker `127.0.0.1`
указывает на сам контейнер: используйте доступное из контейнера имя или адрес сервера модели.
В приведённом примере loopback подходит для локального режима разработки.

## Доступ по IP или домену

Для доступа по IP выберите «По IP сервера», укажите порт приложения и внешний IP. Например,
`http://203.0.113.10:3000`. Если сервер за NAT, нужен адрес, по которому к нему подключается браузер.

```bash title="terminal.sh"
lct configure --yes --host 203.0.113.10 --web-port 3000 --api-port 3001
```

Для HTTPS выберите «По домену» и введите имя без протокола, порта и пути:

```bash title="terminal.sh"
lct configure --yes --domain slides.example.com
```

DNS домена должен указывать на сервер, а входящие порты 80 и 443 должны быть доступны.
Мастер включает профиль Caddy для получения и продления сертификата; порт приложения
привязывается к loopback. Настройки DNS и firewall выполняет владелец сервера.
Порты приложения и API должны различаться и не занимать 80/443 в режиме HTTPS.

Чтобы вернуться с домена к HTTP по IP:

```bash title="terminal.sh"
lct configure --yes --domain= --host 203.0.113.10 --web-port 3000
```

## Документация API и поиск

<Figure
  src="/images/cli/settings.png"
  width={1216}
  height={730}
  alt="Вопрос мастера о включении документации API, по умолчанию выбран ответ «Нет»"
  caption="Настройки установки: документация API выключена по умолчанию."
/>

Документация API выключена по умолчанию. Переключатель включает Swagger в приложении
и [консоль](/docs/api/console/) на сайте документации: без него пробный запрос получит 404.
Статьи Markdown этот переключатель не публикует и не прячет.

```bash title="terminal.sh"
# Выключить Swagger и веб-поиск, остальные параметры сохранить.
lct configure --yes --no-docs --no-search

# Включить документацию API и контейнер поиска SearXNG.
lct configure --yes --docs --search
```

Когда API-документация включена, Swagger доступен в приложении по `/api/docs`, схема — по
`/api/docs-json`; при включении эти страницы открыты без входа. Консоль на сайте документации
логинится отдельно и ходит в приложение. Для чужого адреса документации на сервере приложения
задают `DOCS_PUBLIC_URL`. Поиск включается отдельным профилем `search`. При применении мастер
остановит контейнеры отключённых возможностей.

## Сохранение и применение

  src="/images/cli/summary.png"
  width={1216}

  alt="Сводка адреса, администратора и возможностей перед сохранением настроек"
  caption="Сводка перед записью настроек. Домен, почта и каталог демонстрационные."
/>

`--no-start` сохраняет настройки без применения. Применить их позже можно командой `lct start`:

```bash title="terminal.sh"
lct configure --yes --no-docs --no-start
lct start
```

Если отложено отключение поиска или HTTPS, `lct start` сам по себе не останавливает ранее
запущенные контейнеры исключённых профилей. Для этого из каталога установки выполните
`docker compose stop search` или `docker compose stop proxy` соответственно.

Файл `.env` получает права 0600. При новой установке генерируются отдельные `AUTH_SECRET`,
`API_SERVICE_TOKEN`, `MODEL_KEYS_SECRET`, `SEARXNG_SECRET` и пароль PostgreSQL. Повторная настройка
сохраняет их. При утрате `.env` рядом с существующей БД восстановите его из резервной копии:
новый ключ шифрования не расшифрует сохранённые ключи моделей.

После ручной правки `.env` используйте `lct start` или `docker compose up -d` из каталога
установки. `lct restart` перезапускает существующие контейнеры с прежним окружением.
