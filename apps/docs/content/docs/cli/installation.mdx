## Чистая Ubuntu

Подготовьте чистую Ubuntu, доступ по SSH под root или пользователем с sudo и данные подключения
к модели. Вручную устанавливать Node, Python или Docker перед запуском не требуется.
Понадобится доступ к сети для скачивания пакетов, исходников и сборки образов; `lct doctor`
проверяет наличие более 5 ГБ свободного места, а фактический объём зависит от образов и данных.

Выполните в терминале сервера под root или пользователем с sudo:

```bash title="terminal.sh"
curl -fsSL https://raw.githubusercontent.com/TheAweny/case-14-ai-presentation-designer-team-41/main/install.sh | bash
```

Если `curl` отсутствует на минимальной Ubuntu, установите его один раз:

```bash title="terminal.sh"
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

При входе под root команды APT выполняются без `sudo`.

Команда из `main` устанавливает опубликованный в этой ветке код. При проверке другой ветки
скачивайте `install.sh` из неё и запускайте из соответствующего клона проекта.

Bash проверяет Ubuntu, устанавливает Git и сертификаты, Docker из официального APT-репозитория
с Compose и buildx, совместимый Node с Corepack. Скачанный архив Node проверяется по SHA-256
из официального манифеста. Python и LibreOffice работают внутри образа движка.

CLI пока собирается из исходников через Yarn и Nx; первая установка требует загрузки
зависимостей и сборки контейнеров. Публичных готовых архивов CLI установщик не предполагает.

По умолчанию root устанавливает проект в `/opt/lct26`, обычный пользователь — в `~/lct26`.
Другой каталог задаётся через `LCT_HOME`; другой Git-репозиторий — через `LCT_REPO`.
При запуске `bash install.sh` из клона используется этот клон. Bootstrap не выполняет `git pull`,
не сбрасывает изменения и не заменяет чужую команду `lct`.

Этапы отображаются компактно; подробный лог bootstrap сохраняется в приватном каталоге
`/tmp/lct-bootstrap.*`, его путь выводится в терминал. При `NO_COLOR` или перенаправлении вывода
цвет и анимация отключаются. Ввод мастера читается из терминала даже при `curl | bash`.
Без терминала нужен явный `--yes` со всеми необходимыми параметрами.

Заставка, заголовки и длинные полосы используют нейтральный градиент от серого до светло-серого
и мягкого белого. При загрузке
файла процент рассчитывается по полученным байтам и размеру из ответа сервера. Если размер
неизвестен, полоса показывает движение без процента; сборка и ожидание сервисов работают так же.
Ширина подстраивается под терминал, включая SSH с телефона. Для статичного градиента задайте
`LCT_REDUCED_MOTION=1`; для простого вывода без цвета и управления курсором — `NO_COLOR=1`.
Терминалы без truecolor получают доступные цвета из палитры 256 или 16 цветов.

## Мастер настройки

После подготовки сервера установщик автоматически открывает `lct onboard`. Пройдите четыре шага:

1. **Подключение модели.** Выберите VK AI Space, Yandex AI Studio или совместимый API,
   введите данные подключения и дождитесь проверки ответа. «Тестовые ответы» подходят для
   демонстрации, но не создают новые презентации.
2. **Администратор.** Укажите почту для входа, имя и пароль; мастер попросит повторить пароль.
3. **Доступ и возможности.** Выберите IP или домен, настройте порт и дополнительные возможности.
   Документация API выключена по умолчанию. Веб-поиск можно выключить вместе с SearXNG.
4. **Сохранение и запуск.** Проверьте сводку, подтвердите запись `.env` и запуск сервисов.

Для домена DNS должен указывать на сервер, а порты 80 и 443 быть доступны снаружи. Профиль
`https` запускает Caddy, который получает и продлевает сертификат. Порт самого приложения
публикуется только на loopback. При доступе по IP используется HTTP и выбранный порт приложения.
Укажите внешний IP сервера в мастере или через `--host IP`, если он отличается от адреса
сетевого интерфейса (например, сервер находится за NAT).
Настройка firewall и DNS остаётся у владельца инфраструктуры.

Настройки сохраняются в `.env` с правами 0600. Каждая новая установка создаёт независимые
`AUTH_SECRET`, `API_SERVICE_TOKEN`, `MODEL_KEYS_SECRET`, `SEARXNG_SECRET` и пароль PostgreSQL.
При повторной настройке они сохраняются: менять ключ шифрования без переноса данных нельзя.
Если `.env` утрачен, но том PostgreSQL сохранился, мастер требует восстановить настройки.
Для ручных значений CLI поддерживает комментарии и кавычки; вместо ссылок `${OTHER_VARIABLE}`
используйте буквальные значения в одинарных кавычках, чтобы сохранить одинаковые секреты у CLI и Compose.

## Установка без вопросов

Пример установки VK AI Space из клона. Перед запуском подготовьте выданный провайдером
Project ID и адрес приложения; `PROJECT_UUID` замените своим UUID. Секреты вводятся скрыто:

```bash title="terminal.sh"
read -rsp 'API-ключ модели: ' LCT_MODEL_API_KEY; echo
read -rsp 'Пароль первого администратора: ' LCT_INSTALL_ADMIN_PASSWORD; echo
export LCT_MODEL_API_KEY LCT_INSTALL_ADMIN_PASSWORD
bash install.sh --yes --provider vk --project-id PROJECT_UUID \
  --admin-email you@example.com --admin-name 'Администратор' \
  --domain slides.example.com --no-docs --no-search
unset LCT_MODEL_API_KEY LCT_INSTALL_ADMIN_PASSWORD
```

В CI переменные заполняются из хранилища секретов без `read`. Для запуска без клона те же
флаги передаются после `bash -s --`:

```bash title="terminal.sh"
curl -fsSL https://raw.githubusercontent.com/TheAweny/case-14-ai-presentation-designer-team-41/main/install.sh \
  | bash -s -- --yes --provider vk --project-id PROJECT_UUID \
    --admin-email you@example.com --admin-name 'Администратор' \
    --host 203.0.113.10 --no-docs --no-search
```

В этом варианте `LCT_MODEL_API_KEY` и `LCT_INSTALL_ADMIN_PASSWORD` уже должны быть экспортированы
в shell. Команда не задаёт вопросов. Для IP укажите реальный внешний адрес сервера;
`203.0.113.10` приведён для примера.

`--no-start` сохраняет конфигурацию без запуска; затем используйте `lct start`.
`--domain=` переключает установленный сервис с домена обратно на IP.
`--provider offline` включает только записанные тестовые ответы: новые презентации не генерируются.

## После установки

По завершении мастер выводит адрес приложения и почту администратора. Откройте адрес в браузере
и войдите с паролем, который указали при установке. Для новых пользователей создайте аккаунты
через [раздел пользователей CLI](/docs/cli/users/) или административный интерфейс приложения.

`lct` открывает меню с адресом и состоянием контейнеров. Доступны запуск и остановка,
пользователи, подключение модели, настройки, логи, диагностика, резервное копирование и обновление.
Клавиши выбора показывает сам терминал. Ctrl+C отменяет текущий ввод; из вложенных действий
можно вернуться в главное меню.

Подробные инструкции: [настройка модели и адреса](/docs/cli/configuration/),
[запуск, логи и диагностика](/docs/cli/service/), [пользователи и доступ](/docs/cli/users/),

Те же операции доступны командами:

```bash title="terminal.sh"
lct status
lct configure
lct model
lct doctor
lct logs api
lct user list --login-email you@example.com
lct user add colleague@example.com --name 'Colleague' --role user
lct user disable colleague@example.com
lct user enable colleague@example.com
lct user role colleague@example.com --role admin
lct user password colleague@example.com
lct user revoke-sessions colleague@example.com
```

Управление аккаунтами использует актуальный пароль администратора и существующие ограничения
API. Для работы без терминала задайте `LCT_ADMIN_EMAIL` и `LCT_ADMIN_PASSWORD` в shell;
для создаваемого или меняемого аккаунта передайте нужные параметры флагами. Сессия CLI не
сохраняется на диске и отзывается после выполнения операции. Забытый пароль администратора
восстанавливается через `lct user admin [email]` с новым паролем.

После ручного изменения `.env` примените настройки через `docker compose up -d` из каталога
установки; простой `restart` не перечитывает переменные окружения контейнера. Если вручную
убрали профиль `search` или `https`, остановите соответствующий контейнер.

## Резервные копии и обновления

`lct backup` создаёт архив вне каталога установки и показывает путь. В нём `.env`, `data/`,
`runs/`, SQL-дамп PostgreSQL и метаданные версии. На время снимка останавливаются работавшие
web/API/engine; после снимка, в том числе при ошибке, запускаются именно эти контейнеры.
PostgreSQL должен быть запущен. Процессы записи, запущенные вне Docker, остановите отдельно.

Каталог копии имеет права 0700, архив — 0600: он содержит секреты. Скопируйте его на отдельный
носитель. Внешние каталоги шрифтов, сертификаты прокси и кэш поиска в архив не входят.

Для восстановления сначала распакуйте архив в новый приватный каталог, изучите `metadata.json`
и остановите процессы записи. Восстанавливайте `.env`, `data/`, `runs/` и `database.sql` вместе,
используя совместимую версию PostgreSQL. Перед заменой сохраните текущее состояние.
Автоматической команды восстановления пока нет.

`lct update` требует чистую ветку с upstream и допускает только fast-forward. Перед изменением
кода делает резервную копию, затем собирает CLI и ранее работавшие сервисы и проверяет их
доступность. При ошибке показывает путь копии и команды восстановления кода. Автоматического
отката миграций или данных нет.
