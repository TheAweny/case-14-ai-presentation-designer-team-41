и состояние контейнеров. Выберите «Адрес приложения», чтобы ещё раз вывести ссылку для браузера.

## Запуск, остановка и состояние

| Команда           | Результат                                                             |
| ----------------- | --------------------------------------------------------------------- |
| `lct start`       | Собирает образы и запускает сервисы активных профилей Compose         |
| `lct stop`        | Останавливает и удаляет контейнеры; том БД и файлы данных сохраняются |
| `lct status`      | Показывает таблицу состояния контейнеров Compose                      |
| `lct restart`     | Перезапускает сервисы с существующей конфигурацией контейнеров        |
| `lct restart api` | Перезапускает только API                                              |

Например, после перезагрузки сервера:

```bash title="terminal.sh"
lct status
lct start
lct doctor
```

После изменения настроек используйте `lct start`, чтобы пересоздать контейнеры с новым
окружением. Длительная первая сборка ожидаема: её вывод сохраняется в `data/logs/service.log`.

## Логи

```bash title="terminal.sh"
lct logs
lct logs api
lct logs engine
lct logs proxy
```

Команда показывает последние 100 строк и продолжает следить за выводом. Ctrl+C завершает
просмотр. Пункт «Последние логи» в меню показывает последние строки без непрерывного слежения.
Допустимые имена сервисов: `postgres`, `engine`, `api`, `web`, `search`, `proxy`.

Логи установки контейнеров находятся в `data/logs/install.log`, последующих операций запуска
и остановки — в `data/logs/service.log`. Путь отдельного лога Bash-установщика выводится при
установке и находится в приватном каталоге `/tmp/lct-bootstrap.*`.

## Диагностика

```bash title="terminal.sh"
lct doctor
```

Диагностика проверяет Node, Docker, Compose/buildx, свободное место, администратора и секреты,
затем обращается к модели, API и странице входа. Проверка модели использует реальное
подключение, поэтому требует доступности провайдера. Код завершения 0 означает, что все
проверки успешны; 1 — что найдена хотя бы одна проблема.

| Что произошло                     | Что проверить                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `lct` не найден                   | Используйте полный путь `/usr/local/bin/lct` для root или `~/.local/bin/lct`; добавьте каталог в `PATH` |
| Docker не отвечает                | Службу Docker, права текущего пользователя; затем повторите `lct start`                                 |
| Модель не отвечает                | `lct model`: ключ, адрес, Project ID или ID каталога; сетевой доступ к провайдеру                       |
| API или веб не отвечают           | `lct status`, `lct logs api`, `lct logs web`, затем `lct start`                                         |
| HTTPS не готов                    | DNS и порты 80/443; подробности — `lct logs proxy`                                                      |
| Занят порт                        | Найдите процесс командой `ss -ltnp`, затем выберите другой порт через `lct configure`                   |
| Мало места                        | `df -h`, объём логов и образов Docker; `doctor` требует более 5 ГБ свободного места                     |
| БД найдена, но `.env` отсутствует | Восстановите настройки из согласованной резервной копии                                                 |

Вопросы в интерактивном режиме требуют TTY. Для установки из автоматизации используйте
[режим без вопросов](/docs/cli/installation/#установка-без-вопросов); для операций с пользователями —
[параметры авторизации](/docs/cli/users/#автоматизация).

## Несколько установок

`lct` привязан к каталогу, в котором был собран. Переменная `LCT_HOME` позволяет указать другую
установку явно:

```bash title="terminal.sh"
LCT_HOME=/srv/lct-demo lct status
```

Убедитесь, что команда относится к нужной установке перед изменением настроек или обновлением.
Это руководство относится к Docker-установке через `install.sh`. Инфраструктура командного
production-развёртывания описана отдельно в [DEPLOYMENT.md](/docs/operations/).
