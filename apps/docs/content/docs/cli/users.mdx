Первого администратора создаёт мастер установки. Для дальнейшего управления аккаунтами
выполните `lct user` или выберите «Пользователи» в главном меню. Потребуются актуальная почта
и пароль администратора, а сервис API должен быть запущен.

## Создать пользователя

Выберите «Создать аккаунт», укажите почту, имя, пароль и роль. Либо выполните:

```bash title="terminal.sh"
lct user add colleague@example.com --name 'Анна' --role user
```

CLI спросит новый пароль аккаунта и данные администратора. Новый пароль должен содержать
от 8 до 200 символов. Роль `user` назначается по умолчанию; `admin` даёт права управления
пользователями. Самостоятельной регистрации в приложении нет: передайте пользователю адрес
приложения и его данные для входа по принятому у вас каналу.

## Список и действия с аккаунтом

```bash title="terminal.sh"
lct user list
lct user role colleague@example.com --role admin
lct user disable colleague@example.com
lct user enable colleague@example.com
lct user password colleague@example.com
lct user revoke-sessions colleague@example.com
```

Список показывает id, почту, имя, роль и состояние аккаунта. Вместо почты в командах изменения
можно передать id. В меню те же операции находятся в «Выбрать аккаунт» → «Действие с аккаунтом».

Блокировка запрещает доступ, разблокировка возвращает его. Сброс пароля запрашивает новый
пароль. «Отозвать все сессии» завершает существующие сессии выбранного пользователя.
API не позволяет понизить роль или отключить собственный аккаунт и требует сохранить
как минимум одного администратора.

Команды работают через API от имени администратора. Для команды создаётся временная сессия,
которая отзывается по завершении операции; в меню она живёт до выхода из раздела.
Пароль и токен сессии CLI не сохраняет на диске.

## Восстановить администратора

Если пароль администратора забыт, владелец установки с доступом к серверу может выполнить:

```bash title="terminal.sh"
lct user admin admin@example.com
```

Команда спросит имя и новый пароль, запишет их в `.env` и применит настройки к запущенному API.
Если API остановлен, запустите его через `lct start`: новый пароль применяется при старте API.
Существующий аккаунт с указанной почтой снова получит роль администратора и будет включён.
Для этой операции текущий пароль администратора не требуется.

Восстановление администратора записывает пароль в настройки установки. Это отличается от
обычной команды `lct user password`, которая меняет аккаунт через API и не переписывает `.env`.

## Автоматизация

Для работы без терминала передайте учётные данные администратора через окружение shell:

```bash title="terminal.sh"
export LCT_ADMIN_EMAIL='admin@example.com'
read -rsp 'Текущий пароль администратора: ' LCT_ADMIN_PASSWORD; echo
export LCT_ADMIN_PASSWORD
lct user list
lct user disable colleague@example.com
unset LCT_ADMIN_EMAIL LCT_ADMIN_PASSWORD
```

`read` в примере выполняется оператором перед запуском команд; сами команды не задают вопросов.
В CI значения поступают из хранилища секретов. Вместо `LCT_ADMIN_EMAIL` можно использовать
`--login-email admin@example.com`; `--login-password` также поддерживается, но значение в аргументе
будет видно в списке процессов и может попасть в историю shell.

Для создания или сброса пароля без TTY необходимо явно передать `--password`; для создания
нужны также почта и `--name`, для смены роли — `--role user|admin`. Обычный интерактивный ввод
пароля удобнее, когда автоматизация этих операций не требуется.

`LCT_INSTALL_ADMIN_PASSWORD` используется мастером установки и не заменяет `LCT_ADMIN_PASSWORD`:
для управления аккаунтами требуется **актуальный** пароль администратора, который мог измениться
после установки.
