`lct generate` запускает пайплайн без браузера: читает шаблон и контент, строит план,
создаёт варианты и сохраняет результаты. Для работы нужна подключённая живая модель;
режим «Тестовые ответы» для этой команды не подходит.

## Первый запуск

Из каталога установки:

```bash title="terminal.sh"
lct start
lct generate configs/run.example.yaml
```

Пример использует `examples/template.pptx` и `examples/brief.md`. Для собственных файлов
скопируйте конфиг и измените пути:

```bash title="terminal.sh"
cp configs/run.example.yaml configs/run.local.yaml
```

Фрагмент, который обычно меняют. Схема требует и остальные поля полного примера
`configs/run.example.yaml`: без `models`, `seed` и `auditProfile` файл не пройдёт проверку.

```yaml title="run.local.yaml"
templatePath: /srv/presentation-input/template.pptx
contentPath: /srv/presentation-input/brief.md
slideCount: 10
layoutVariants:
  - dense
  - balanced
  - airy
goal: Получить решение о запуске проекта.
audience: Руководители подразделений
outputDir: runs
```

Что команда читает из файла:

| Поле | Как используется |
| --- | --- |
| `templatePath` | `.pptx` до 50 МБ, настоящий пакет PowerPoint |
| `contentPath` | `.json`, `.md`, `.txt`, `.yaml` или `.yml` до 5 МБ и не длиннее 60 000 символов |
| `slideCount` | целое от 5 до 15 |
| `layoutVariants` | один или несколько из `dense`, `balanced`, `airy` |
| `seed` | неотрицательное целое, уходит в прогон |
| `outputDir` | каталог результата |
| `goal` | зачем колода; если поля нет, берётся первый абзац материала |
| `audience` | для кого колода; поле необязательно |
| `models`, `auditProfile`, `language` | схема их требует или принимает, команда сборки их не читает |

Модель берётся из `.env`: `LLM_BASE_URL`, `LLM_MODEL` и при необходимости `MODEL_API_KEY` с `MODEL_HEADERS`. Поле `models` в YAML на выбор модели не влияет. `language` язык колоды не переключает. `auditProfile` имя профиля в прогоне не выбирает: после сборки читается аудит, который пайплайн записал сам.

```bash title="terminal.sh"
lct generate configs/run.local.yaml
```

Относительные пути к входным файлам разрешаются относительно текущего каталога shell.
Шаблон — `.pptx` до 50 МБ. Контент — текст (`.txt`, `.md`, `.yaml`), документ (`.docx`, `.pdf`)
или таблица (`.csv`, `.tsv`, `.xlsx`, `.json`). Материал готовится так же, как в сервисе:
таблицу читает движок, короткая уходит в бриф целиком, длинная — сводкой по всем строкам и
первыми строками. Таблицы внутри `.txt` и `.md` описываются после текста. В бриф попадает не
больше 60 000 символов.

## Данные и брендбук

Брендбук задаётся в конфиге путём к файлу или архиву: JSON с дизайн-токенами, PDF-гайдлайн,
`.fig`, логотипы, шрифты, примеры слайдов или ZIP и RAR с ними.

```yaml title="run.local.yaml"
contentPath: /srv/presentation-input/sales.xlsx
brandbookPath: /srv/presentation-input/brandbook.zip
# brandbook (по умолчанию) или template: кто побеждает, если брендбук и шаблон расходятся.
brandbookPriority: brandbook
```

Колоду перекрашивают правила, которые брендбук объявляет: токены и цвета или шрифты с ролью в
гайдлайне. Если не объявлено ни одного, сервис выводит правила сам: основной и второй цвет —
из насыщенных цветов, которые повторяются хотя бы в двух логотипах (при равенстве решают
картинки брендбука), цвет текста — из самого тёмного нейтрального, шрифт — из шрифтовых файлов.
Заголовки получают основной цвет. Выведенные правила помечены как `inferred` и уступают любому
объявленному. Что объявлено и что выведено, CLI печатает в начале прогона, а профиль брендбука
сохраняет в `runs/<прогон>/brandbook-profile.json`. Готовый пример — `configs/run.data-brand.yaml`:
таблица регионов из `examples/datasets` и брендбук Northstar из `examples/brandbooks`.

## Где выполняется генерация

Если движок доступен локально по настроенному `ENGINE_URL`, CLI выполняет генерацию на хосте.
Иначе при запущенном API в Docker переносит входные файлы во временный каталог `data/cli/`
и запускает ту же команду внутри контейнера `api`. После завершения временные копии удаляются.

В Docker результат всегда сохраняется в `runs/` установки; CLI сообщает об этом, если
`outputDir` в конфиге указывает другое место. Настройки подключения берутся из `.env` установки:
непустые значения этого файла имеют приоритет над одноимёнными переменными shell.

## Результат и повторный запуск

В `runs/` сохраняются каталоги прогонов с вариантами и артефактами: `deck.pptx`, рендеры,
экспортируемые файлы, аудит и манифест. Конкретные пути команда печатает во время выполнения.
Манифест фиксирует версии агентов, промптов и моделей, seed, хеши и тайминги.

Успешный код завершения команды означает, что завершился хотя бы один вариант; проверьте
вывод и артефакты, если требуются все три. Каждый новый вызов создаёт новый прогон.
Подробности пайплайна — в [статье о пайплайне](/docs/internals/pipeline/). Полный список флагов CLI — в [командах одной строкой](/docs/cli/reference/).
