Этот раздел про стенд, а не про кнопки редактора. Пошаговые статьи про обновление, резервные копии и квоты появятся отдельно. Ниже — то, что уже следует из репозитория.

## Требования

- Node.js 22.13 или новее (`package.json` и `install.sh`).
- Python 3.12 (`requires-python` в `pyproject.toml` движка).
- Docker и Docker Compose для обычного режима. Без Docker установщик предлагает только `--mode local`.
- Менеджеры репозитория: TypeScript — yarn, Python — uv.

## Как поставить

Из клона репозитория `./install.sh` собирает CLI и запускает мастер `lct onboard`. Флаги мастера перечислены в [CLI](/docs/cli/). Мастер спрашивает режим, провайдера модели и администратора, затем может поднять стек.

Файл `compose.yaml` в корне называется проектом `lct26` и поднимает сервисы `postgres`, `engine`, `api`, `search` и `web`. Команды `lct start`, `lct stop`, `lct status`, `lct logs` и `lct restart` вызывают Docker Compose из корня репозитория.

<Warning>
  В документацию не копируются значения из `.env.example`. Там лежат локальные пароли примера.
  Секреты создаёт `lct onboard` и хранит их только в `.env`.
</Warning>

## Модели

Провайдеры мастера: `vk`, `ai-studio`, `openai`, `offline`. Адреса и имена моделей читаются из переменных окружения, среди них `LLM_BASE_URL`, `VLM_BASE_URL`, `IMAGE_BASE_URL`, `LLM_MODEL`, `VLM_MODEL`, `IMAGE_MODEL`, `MODEL_API_KEY`, `MODEL_PROVIDER`. Полный список имён — в `.env.example`. Ключ в интерфейс и в эту документацию не попадает.

## Аккаунты и квоты

Вход держит веб-сервер. Как устроены cookie и заголовки, написано в [доступе к API](/docs/api/access/).

Ограничения аккаунта необязательны. В контракте `accountPolicySchema` есть лимиты на генерацию, ответ ассистента, картинки, правки, параллелизм и хранилище. Меняет их администратор. Статья с экранами и периодами сброса будет позже; схема уже видна в [справочнике](/docs/api/reference/users/).

## Что ещё будет отдельными статьями

- обновление уже установленного стенда;
- резервная копия тома Postgres (`postgres-data`) и каталогов `data/` и `runs/`;
- разбор `lct doctor` по каждому пункту.

`lct doctor` уже проверяет Node, Docker, Compose, buildx, свободное место, администратора, что секреты установки не пустые и не взяты из примера, и отвечает ли модель. Если API или веб не запущены, он пишет адрес `http://localhost:3001/health` и `http://localhost:3000` и подсказывает `lct start`.
