# Журнал решений

Здесь живут только архитектурные инварианты: решения, которые нельзя вывести из кода за минуту и
отмена которых заденет больше одного пакета.

Версии зависимостей, выбор библиотек и настройки инструментов сюда не пишем — им место в
комментарии рядом с самой настройкой или в разделе «Грабли» в `CONTRIBUTING.md`. Тот, кто полезет
менять версию, увидит комментарий в файле; запись в этом журнале он не увидит никогда.

Записи не редактируем и не удаляем. Решение изменилось — добавляем новую и ссылаемся на старую.

## 2026-09-18. Граница между Python и TypeScript — по наличию вызова модели

Всё, что обращается к модели, живёт в TypeScript; всё, что должно быть детерминированным и
воспроизводимым — разбор `.pptx`, вёрстка, экспорт, рендер, измеримые проверки — живёт в Python.
Отсюда же деление аудита на контекстную и детерминированную половины и возможность прогонять
тесты движка без GPU и без сети. Правило закреплено машинно: `@nx/enforce-module-boundaries` на
стороне TypeScript, import-linter на стороне Python.

## 2026-09-18. Слои движка независимы, соединяет их только API

`parser`, `layout`, `visuals`, `export`, `render` и `checks` не импортируют друг друга и знают
только `engine.contracts`; `engine.api` стоит над ними. Описано контрактами import-linter в
`engine/pyproject.toml`. Мотив — менять вёрстку, не задевая парсер, и тестировать слои по
отдельности.

## 2026-09-18. Контракты: Zod — источник правды, Pydantic генерируется

Схемы описываются один раз в `packages/contracts`, из них собирается JSON Schema, из неё —
Pydantic-модели движка. Сгенерированные файлы коммитятся, CI перегенерирует их и падает на любом
расхождении. Альтернатива — держать два описания руками — разъезжается на второй неделе.

## 2026-09-18. Состояние без базы данных

Отдельная СУБД не заводится: результаты прогонов лежат в `runs/`, состояние Mastra — в
LibSQL-файле там же. Это снимает с демо-стенда лишний сервис и делает прогон переносимым вместе с
каталогом.

## 2026-09-18. Профиль шаблона вместо любых условий по шаблону

Ни в коде, ни в конфигах не бывает ветвлений вида «если шаблон такой-то», зашитых названий
макетов, цветов, шрифтов и координат. Всё, что зависит от шаблона, читается из профиля шаблона.
На защите дадут незнакомый шаблон, и сценарий `eval/unknown-template.yaml` существует ровно для
того, чтобы это проверять.

## 2026-09-18. Apache 2.0 и исполняемая политика лицензий

Решение открытое, заказчик говорит о пилоте и внедрении, поэтому выбрана Apache License 2.0 — она
даёт явную патентную оговорку. Зависимости допускаются только под разрешительными и слабыми
копилефт-лицензиями; GPL и AGPL не подходят. Политика не декларативная: `yarn licenses` обходит
дерево обеих экосистем и падает, если в нём появился копилефт.
