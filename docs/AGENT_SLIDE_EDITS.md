# Правки одного слайда агентом

Это план P2, не работающие инструменты. Код по нему не пишется, пока не закрыты отчёты P0 и P1. `edit_slide` не меняется.

## Что есть сейчас

`edit_slide` в `apps/api/src/chats/chat-tools.ts` принимает `deckId`, `slideNumber`, `elementId`, `text`. Объект должен быть текстом, прикреплённым из редактора. Часть `slide-edit` (`packages/contracts/src/chat.ts`) несёт `editId`, `before`, `text`. Редактор пишет это в журнал черновика и откатывает оттуда.

API не читает живой черновик: эндпоинта текущего драфта нет. Хеш «как при последнем чтении» API вычислить не может. Макет, визуал и целый слайд `edit_slide` не применяет.

Сборка одного слайда уже есть: `composedSlideSchema` и `compositionExportRequestSchema` в `packages/contracts/src/generation.ts`. Движок возвращает pptx и `templateIr`. TypeScript pptx не открывает. Обратный импорт в SlideIR — вызов движка, и он уже отдаёт все нативные элементы, включая таблицу и диаграмму.

## Вход инструмента

У `revise_slide_content`, `replace_slide_layout` и `set_slide_visual` во входе необязательное вложение `liveSlideSnapshot`: SlideIR ровно одного открытого слайда. Размер ограничен тем же потолком, что и прочие вложения чата. Инструмент считает `beforeHash` (sha256 канонического JSON этого IR) и кладёт его в часть. Снимок без проверенного хеша не принимается.

Если живого снимка нет, а есть только сохранённая колода и её хеш не с чем сверить, инструмент отказывается. Подменять черновик файлом колоды нельзя.

Просьба человека в чате — уже согласие. Второй кнопки нет.

## Часть `slide-revision`

Часть ничего не записывает в колоду. Поля: `callId`, `revisionId`, `deckId`, `slideNumber`, `tool`, `patternId`, `sourceRevision`, `beforeHash`, `candidateSlide`, `warnings`.

`candidateSlide` — целый импортированный SlideIR, не список `{slotId, text}` и не `slotVisual` отдельно. По `slotId` геометрию не восстановить: это не `elementId`. Нативный визуал лежит элементами IR, не JSON внутри текста.

## Мост редактора

Редактор применяет часть целиком, одним `commitReplaceSlide`:

1. Считает хеш открытого слайда. Несовпадение с `beforeHash` — отказ, нужен новый снимок.
2. Подменяет слайд на `candidateSlide`. `slideId` сохраняется и остаётся текущим. `elementId` нормализуются заново. Сопоставление `slotId` со старыми элементами не делается: экспорт и импорт уже вернули нативные элементы.
3. Одна запись журнала. Undo возвращает слайд, чей хеш был `beforeHash`.
4. Превью только этого слайда. Остальные слайды и файл колоды не переписываются.

## Как собирается кандидат

`revise_slide_content` переписывает тексты текущего макета. `replace_slide_layout` берёт другую композицию того же шаблона. `set_slide_visual` ставит или снимает одну таблицу или диаграмму и переписывает остальные тексты. Ни один не вызывает `edit_slide`.

API зовёт compose-export одного слайда, затем импорт в SlideIR. Fit и покрытие источниками проверяются до показа части. Провал проверки — предупреждения и нет части.

Медиа экспорта лежат в каталоге прогона `agent-revisions/`, не во временной папке. Удаление временного pptx не должно рвать пути картинок кандидата. В часть попадает IR с этими устойчивыми путями.
