# Надёжность чата и выполнения инструментов

Изменения от 2026-10-15 относительно `0780de8`. Основание — семь замечаний высокого
приоритета F01–F07 из предоставленного отчёта и воспроизводящие тесты.

## Среда выполнения

Цикл агента остаётся в процессе TypeScript API. Выделен `ChatToolDispatcher`: он проверяет
режим, набор предложенных модели инструментов, Zod-аргументы и отмену до и после вызова.
Доступ предоставляется к функциям приложения через существующие сервисы. Произвольный shell
и отдельный процесс для исполнения модельного кода этим функциям не нужны.

PostgreSQL advisory lock на отдельном соединении разрешает один ход одного чата между
процессами API. Потеря соединения отменяет ход. Снимок намерения собрать колоду сохраняется
до запуска генерации; после запуска сохраняются идентификаторы прогонов. Повторное одобрение
и запрос с прежним `requestId` возвращают сохранённое состояние. Изменённое содержимое с тем же
идентификатором отклоняется. Новый фронтенд отправляет `requestId`; старые клиенты без него
не получают защиту от повторной отправки обычного сообщения.

Снимки сообщений хранятся в PostgreSQL; после перезапуска оставшийся `streaming` превращается
в явный прерванный ответ. Неизвестный исход инструмента автоматически не переисполняется.
На другом процессе API просмотр получает снимки с интервалом 500 мс, отмена передаётся через
PostgreSQL notification после проверки владельца. Номер SSE относится к текущему соединению;
возобновляемый журнал каждого текстового фрагмента не заявляется.

Отдельный worker пока не добавлен. Для него потребуется устойчивый журнал команд и событий,
владение задачами генерации и согласованный протокол восстановления. Текущий dispatcher можно
переиспользовать при таком выносе. Функциональная изоляция уже применяется, восстановление
после сбоя сохраняет явный статус вместо обещания автоматического продолжения.

Смысловое соответствие перефразированного утверждения оценивает модель. Код проверяет наличие
её цитаты на нужном слайде; это не математическое доказательство эквивалентности утверждений.
Не подтверждённое покрытие и оставшиеся смысловые ошибки явно требуют проверки человеком.

Сохранение терминального ответа выполняется до сообщения об успехе. Ошибка записи показывает
неуспешное состояние. Сбой сохранения уже запущенной сборки и отмена во время её запуска
отменяют связанные прогоны. Удалённый чат не создаётся заново поздней записью прогресса.

## Дополнительные изменения

- Ошибка сборки завершает ход с `failed`, без автоматического повторного запуска моделью.
  Повтор `build_deck` возвращает точный статус последней попытки; новая попытка после ошибки
  требует `retry: true` в следующем ходе и использует тот же одобренный план. Активная или
  успешная сборка повторно не запускается. Недостающий результат считается неизвестным.
  HTTP 429 показывается как отказ провайдера из-за лимита; остановленная сборка не обещает
  готовые варианты позже. Реальные ограничения провайдера этим изменением не снимаются.

- Полный сериализованный запрос чата, включая инструменты и аргументы, ограничен бюджетом
  90 000 символов. Удаляются целые старые ходы, последние требования не обрезаются. Это лимит
  размера запроса, а не токенизатор выбранной модели.
- `read_file` принимает `offset` и `limit`, возвращает `hasMore` и `nextOffset`.
- Размер документа чата проверяется по UTF-8 байтам; отказ записи не выдаётся за успех.
- Общий сигнал основной сборки охватывает иллюстрации и варианты; после завершения всех
  потребителей фоновые обращения отменяются. После терминального события прогресс не пишется.
- Каждый прогон закрывает Mastra в `finally`. Локальное SQLite-хранилище использует встроенный
  API Node через официальный клиентский интерфейс Mastra. Версии Mastra не изменены.
- Сборка API и run-store работает на Windows через общий Node-скрипт, без POSIX-команд.

## Проверка

Тесты используют фейковые модели и движок, без сети и GPU. Подготовленные RED-тесты и GREEN-
исправления сохранены отдельными conventional commits. Полный `pipeline:test`: 205 тестов.
Два браузерных сценария прошли в установленном Microsoft Edge (Chromium): восстановление SSE
и одобрение отредактированного плана с ревизией 7. Тестовый API изолирован от пользовательского.

Команды проверки:

```powershell
yarn nx run contracts:codegen
yarn nx run-many --targets="typecheck,lint,test" --projects="api,web,pipeline,contracts,run-store,registry" --parallel=3
yarn nx run api:build
yarn nx run web:build
$env:E2E_BROWSER_CHANNEL = 'msedge'
yarn nx run web:e2e --config=playwright.chat.config.ts
```

Процент покрытия не измерялся. Взаимодействие нескольких API-процессов проверено на фейковом
PostgreSQL-драйвере; реальный failover PostgreSQL и нагрузочный прогон с живыми моделями здесь
не выполнялись. Бюджет основной генерации ограничен 290 секундами, но фактическая готовность
трёх вариантов за пять минут на живых моделях повторно не измерялась.

Замечания среднего приоритета F09 (полная трассировка попыток провайдеров), F10 (актуальность
смыслового индекса), F12 (все старые исправляющие промпты в реестре) остаются отдельной работой.
F11 улучшен для основного пути, общий deadline альтернативного CLI-пути ещё не введён.
