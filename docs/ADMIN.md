# Администрирование

`/admin` доступен администраторам. Раздел задаётся `view=overview|people|limits|metrics`;
`view=limits&account=<id>` открывает ограничения конкретного аккаунта. Старый адрес
`?settings=users` переводит в панель. Права на операции по-прежнему проверяет API.

## Пользователи и настройки

Поиск по имени и почте совмещается с фильтрами роли и доступа. Профиль позволяет изменить
имя и почту; конфликт почты оставляет форму открытой. Создание, роли, отключение, сброс пароля
и удаление используют существующие операции API. Меню пользователя ведёт к его ограничениям
и отзыву сессий. Защита своего аккаунта и последнего администратора остаётся на сервере.

В настройках есть общая политика и личные исключения. Отсутствие ключа наследует общую
политику, `null` явно снимает ограничение, объект задаёт лимит. «Вернуть всё к общей политике»
готовит пустое исключение; изменение применяется только кнопкой сохранения. Отмена возвращает
последнюю сохранённую политику. Пока редактируется период, счётчики соответствуют сохранённой
политике, после сохранения API пересчитывает окно. Панель предупреждает о несохранённых
правках при смене аккаунта или вкладки администрирования; закрытие и перезагрузка вкладки
защищены `beforeunload`. Подключения моделей открываются из настроек отдельным разделом.

## Что означают показатели

Источник — `GET /account-usage/:id`. Счётчики отражают операции за действующее окно лимита:
`start` включительно, `end` исключительно. Без периодического лимита — всё время. Счётчики
используют время допуска операции (`admitted_at`), а не время её окончания. Три варианта
колоды считаются одной генерацией. Активные сборки показаны отдельно от завершённых операций.
Хранение — текущий объём файлов и сохранённых редакций.

Одна Server Action читает список и активность с максимум четырьмя параллельными запросами к
API; каждый запрос ограничен 15 секундами. Ответы активности валидируются контрактом.
Ошибочный аккаунт остаётся в списке с неизвестной активностью, вместо нулей. Панель показывает
число загруженных аккаунтов и время окончания чтения. Обновление сохраняет предыдущие данные
до получения результата; ошибка обновления явно помечает их как предыдущие.

Итоги относятся к найденным аккаунтам. Счётчики складываются только при наличии всех данных
и совпадении `start`/`end` каждого счётчика у всех найденных аккаунтов. Иначе итог — «—» с
объяснением. Периоды видны рядом со счётчиками каждого аккаунта. Чтение нескольких аккаунтов
не является транзакционным снимком всей установки. История по произвольным датам, стоимость,
токены, длительность и причины ошибок этим API не предоставляются.

## Проверка

`yarn nx run web:test`, `yarn nx run web:typecheck`, `yarn nx run web:lint`.
Браузерные сценарии: `yarn nx run web:e2e-chat --args="admin-dashboard.e2e.ts settings-responsive.e2e.ts"`.
Они используют изолированный API с записанными данными, без провайдера моделей.
