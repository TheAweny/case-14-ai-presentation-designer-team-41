## Ограничения первого этапа

- `model-plan.json` фиксирует writer, rewriter, planner, critic и назначенный vision;
  значения thinking/effort помечены как запрошенные. Выбор image через настройки или env
  и сведения о фактических токенах пока не сведены в этот артефакт.
- Один объект `AttemptBudget` передаётся текстовым ролям и vision всех вариантов сборки.
  Лимит 110 относится к повторам, а не ко всем первым запросам и не доказывает SLA.
- Начало дедлайна перенесено на вход в `start`. Чтение материалов и разрешение моделей
  ограничены ожиданием с отменой. Runner получает тот же абсолютный deadline и оставляет
  60 секунд после первого визуального прохода и 12 после последнего. Это резервы времени,
  а не измеренная гарантия скорости внешнего движка. Запись состояния в БД и файлов во время создания run
  пока не имеет отдельного жёсткого таймаута; задержки этих операций остаются риском.
- Измеренный результат трёх вариантов за пять минут на целевой модели ещё не получен.

## Продолжение: замечание Bugbot и эксперимент выбора макетов

Пользователь после консультации с Astra согласовал проверку сохранения структуры при
смене макетов. Общий автор содержимого не внедряется. Описание и ограничения эксперимента:
[LAYOUT-REMAP-EXPERIMENT.md](LAYOUT-REMAP-EXPERIMENT.md).

Повторный Bugbot на `e777d01` нашёл одно новое замечание: `pictures` отражал только текущий
проход, хотя итоговый аудит объединял ответы всей колоды. Исправлено в `824c707`:
сохраняются уникальные идентификаторы актуальных слайдов с загруженными превью. Пропавшее
превью перепроверяемого слайда удаляет его из счётчика; ошибка модели при наличии картинки
не удаляет. Исчезнувшие из импорта слайды не наследуются. `9d5b378` убирает предупреждение
линта в тесте. PR #6 на этом HEAD имеет зелёные CI, license policy и Cursor Bugbot.

Независимые проверки исправления: 36 тестов runner/visual-review прошли; stdin probe
с тремя исходными слайдами и последующим импортом двух дал pictures/reviews 2/2,
при пропавшем превью — pictures 1/failures 1, при ошибке JSON модели — pictures 2/reviews 1.

Ветка эксперимента сохраняет режим `density` по умолчанию. `preserve-block-count` доступен
только программно и фиксируется в manifest. CLI сравнивает `CompositionPlan`
(`runs/<run-id>/composition-plan.json`), а не `plan.json` варианта: тот хранит уже написанные
слайды. Повторный `pipeline:compare-layout-remap` на `runs/remap-experiment/synthetic-*.json`
дал для dense 11 изменений числа блоков при `density` и 0 при `preserve-block-count`,
разных макетов 3 и 2; balanced и airy без изменений. Это структурный счёт синтетического
примера, не оценка качества. Несовместимый исторический план по-прежнему отклоняется.
Независимая проверка runner/workflow (82 теста), `pipeline:typecheck` и `pipeline:lint`
пройдена. Отдельный stdin-probe из 600 детерминированных сравнений сохранил число блоков
в строгом режиме и не изменил вход. Ещё 750 сравнений с исходным `remapPlan` на
`81ce86b` совпали с режимом по умолчанию. Итог общего набора тестов pipeline этим журналом
зафиксирован: `pipeline:test` — 38 файлов, 464 теста пройдено. `nx run-many` для pipeline и api
(test, typecheck, lint, build и 5 зависимых задач) завершился успешно: 13 задач, из них 10 из кэша,
включая `api:test` (76 файлов пройдено, 1 пропущен; 427 тестов пройдено, 3 пропущено).

Эксперимент оформляется отдельным stacked PR поверх `theaweny/template-aware-agents`
после push `81ce86b`; HEAD новой ветки — `theaweny/layout-remap-experiment`. Номер PR
здесь не фиксируется. Синтетические JSON из `runs/remap-experiment/` в Git не входят;
спеки `remap-evaluation.spec.ts` и `remap-cli.spec.ts` входят и воспроизводят сравнение.
Незакоммиченные `packages/pipeline/package.json` и `yarn.lock` с QR-зависимостями остаются
ранним WIP и в этот эксперимент не входят.

В этом эксперименте общий автор, QR-инструмент и адресное редактирование слоёв не
добавлялись. Экспорт исходного PPTX/POTX принят первым этапом в `c80ceef`; QR и адресное
редактирование слоёв ещё предстоят. Новый bundle экспорта этим этапом не делается.
