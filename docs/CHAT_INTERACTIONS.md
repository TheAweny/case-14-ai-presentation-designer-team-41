# Взаимодействие с чатом

Поле ввода общее для страницы чата и панели редактора. Текст, файлы и выбранный шаблон
сохраняются в хранилище вкладки по идентификатору чата и переживают перемонтирование поля.
После полной перезагрузки страницы локальные файлы и неотправленный черновик не сохраняются.

`/` открывает выбор существующих режимов `chat`, `plan`, `auto`. В редакторе `@` открывает
слайды и объекты текущей колоды: выбор закрепляет ссылку, а отправка снимает актуальный
контекст. Меню поддерживают стрелки, Enter, Escape и русский поиск. Кнопка `+` предлагает
материалы и контекст редактора. Шаблон выбирается или загружается отдельной кнопкой рядом с `+`.

Во время ответа кнопка остановки доступна при любом содержимом поля. Enter не останавливает
агента и не отправляет следующий черновик. Результат отмены подтверждает сервер; при ошибке
есть отдельная кнопка повторной остановки. Остановка до отправки хода не позволяет позднему
результату загрузки файлов запустить агента.

## Повтор и восстановление

- У сообщения один `requestId` и снимок параметров: режим, модель, вложения и контекст.
  Транспортные повторы сохраняют этот снимок. Одновременная отправка второго хода блокируется.
- При потерянном подтверждении сначала читается серверный документ. Принятый ход только
  досматривается. Временные ошибки чтения состояния повторяются с задержками.
- Временные сетевые ошибки и HTTP 408, 429, 500, 502, 503, 504 допускают ограниченные
  автоматические повторы. Задержка растёт и содержит небольшой случайный разброс;
  `Retry-After` имеет приоритет. При задержке больше 10 секунд автоматический цикл заканчивается.
- Обрыв SSE восстанавливается через снимок чата и подключение к существующему потоку.
  Новая генерация этим действием не запускается. После исчерпания попыток доступно ручное
  восстановление соединения.
- После сбоя загрузки можно повторить отправку с прежними файлами. Успешно завершённые
  загрузки переиспользуются. Вернуть сообщение в пустое поле можно до отправки POST или после
  явного отказа до начала хода: при неизвестном исходе запроса сначала требуется сверка с сервером.
- «Повторить ответ» — отдельный новый ход после ошибки агента. Он доступен только для
  последнего ответа, если в нём были текст, ошибка и инструменты чтения. Вызовы сборки,
  изменения слайда, неизвестные инструменты и интерактивные карточки исключают такой повтор.

Логика сетевых повторов находится в `apps/web/src/lib/chat-store.ts` и `chat-retry.ts`.
Они используют существующие API и Zod-контракты. Сервер продолжает отвечать за идемпотентность
и выполнение инструментов.

## Проверка

```powershell
yarn nx run-many '--targets=lint,typecheck,test' '--projects=web,api'
yarn nx run web:e2e-chat
```

Браузерные тесты используют отдельный API с фиксированными ответами и каталог Next
`.next/chat-e2e`; модели, PostgreSQL и настоящий API им не нужны. При использовании
установленного браузера можно задать `E2E_BROWSER_CHANNEL`, например `msedge`.

## Основная модель и модели задач

`writer` хранит основную модель. Без отдельного назначения `assistant`, `planner` и `critic`
используют её; выбор модели в чате заменяет модель ассистента и основную модель текстовой
сборки. Явные назначения планировщика и критика сохраняют приоритет; меню чата показывает их.
`vision` и `image` на текстовую модель не переключаются.

Настройки показывают одну основную модель, свёрнутые назначения текстовых задач и отдельный
блок изображений. Назначения, существовавшие до обновления, сохраняются. `kind: default`
явно выбирает основную модель даже поверх отдельной роли администратора; `unassigned`
снимает личное назначение и возвращает общие настройки. Администратор меняет общие
назначения, остальные пользователи — личные.

Список чата разрешает умолчание той же роли, которую использует сервер (`assistant`, затем
`writer`). `null` означает следование настройкам; недоступный выбор не заменяется первой
моделью из списка. Выбор сохраняется в `chats.model` через PATCH и загружается с документом.
Сохранение сообщений текущего хода не перезаписывает модель следующего. Быстрые изменения
сохраняются последовательно; при ошибке сохранения предпочтения есть отдельный повтор,
который не блокирует разговор.

## Действия при ошибке модели

Необязательное поле `failure` части `error` содержит тип причины, модель, подключение и
`retryAt`. Старые сообщения без него отображаются как неизвестная ошибка. Тела ответов
провайдера не возвращаются в диагностике новых HTTP-ошибок. Сбой сети браузера обрабатывается
отдельно: восстановление SSE не повторяет вызов модели.

В карточке можно повторить безопасный ответ, выбрать другую модель и явно нажать
«Повторить с …», вернуть запрос с уже загруженными вложениями в пустой черновик или открыть
настройки подключения. Выбор в карточке безопасного повтора не меняет настройки до нажатия
повтора. Для хода с изменяющими инструментами доступно продолжение в чате; смена модели
меняет модель следующего сообщения, но не воспроизводит выполненные операции.

При 429 кнопка повтора учитывает `Retry-After`, включая дату HTTP. Длинная задержка завершает
автоматические повторы провайдера вместо досрочного повторного запроса. Смена модели или
подключения — явное действие пользователя. Результаты и ошибки предыдущей попытки остаются
в истории. Полный повтор создаёт новый `requestId`, сохраняя текст, режим и вложения.

## Анимации и ход задач

Меню раскрываются от кнопки за 200 мс и закрываются за 120 мс. Плюс поворачивается пружиной,
иконка отправки плавно превращается в остановку и остаётся смонтированной во время отправки.
Подсказки `/` и `@`, состояния инструментов и раскрытие этапов используют Motion.
При `prefers-reduced-motion` перемещения и вращения отключены.

Карточка сборки показывает этапы и прогресс, активный этап выделен. После перезагрузки
завершённой сборки список этапов восстанавливается запросом её сохранённых событий.
Чтение истории не запускает генерацию и не предлагает повтор выполненных инструментов.
