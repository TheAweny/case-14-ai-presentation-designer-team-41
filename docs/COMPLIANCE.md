# Соответствие требованиям

Этот файл фиксирует обязательные требования кейса и разъяснения модератора. Он отличает целевую
архитектуру от подтверждённой реализации, чтобы команда не выдавала контракт или unit-тест за
готовый конкурсный результат.

Обновление 27 сентября: работает отдельный single-deck real-model путь с PPTX/PDF/PNG,
fit-check/repair и persisted API. Три датасетных шаблона прошли технический экспорт, но это
не unknown-template holdout и не 3×3 quality gate. Проверенный API-прогон — 13.618 с.
Подробные evidence и нерешённые вопросы — `docs/GENERATION.md`; таблица ниже описывает
более широкий конкурсный gate, а не отсутствие single-deck реализации.

## Источники

- техническое задание кейса и материалы организаторов;
- разъяснения модератора в чате задачи от 21–23 сентября 2026;
- критерии сдачи от официального канала от 22–23 сентября 2026.

## Обязательные требования

| Требование                            | Критерий доказательства                                            | Текущий статус                                                          |
| ------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Незнакомый пользовательский PPTX      | Зафиксированный unknown-template run без ветвлений по шаблону      | Не подтверждено                                                         |
| Три содержательно различимых варианта | Один plan, три стратегии, объяснимые различия                      | Не реализовано                                                          |
| <= 5 минут на все три варианта        | Замер от пользовательского запроса до готовности всех артефактов   | Не подтверждено                                                         |
| Editable PPTX                         | Открытие в PowerPoint/LibreOffice, нативные текст и visuals        | Частично: single-deck real-model PPTX с нативным текстом                |
| PDF и HTML                            | Три формата на каждый вариант, проверки артефактов                 | PDF single-deck реализован; HTML нового пути нет                        |
| Детерминированный аудит               | Findings с rule, evidence и объектом; passing/failing fixtures     | Single-deck предварительные проверки реализованы; полный gate не закрыт |
| Контекстный аудит                     | Findings с source refs, confidence и proposal                      | Single-deck предварительные проверки реализованы; полный gate не закрыт |
| Выборочные исправления                | Пользователь выбирает finding; новый артефакт и re-audit           | Не реализовано                                                          |
| 3x3 evidence matrix                   | 9 колод, 27 экспортов, без ручного редактирования                  | Не подтверждено                                                         |
| Воспроизводимая сдача                 | Public/expert-access repo, README, модели и настройки без секретов | Частично: README и лицензия есть; clean-clone run не подтвержден        |
| Презентация проекта                   | При применимости: слайды 7–11 сохранены по обязательному шаблону   | Не начато                                                               |

## Расширение продукта

Следующие возможности добавляются поверх обязательного режима и не уменьшают конкурсный gate:

| Расширение      | Правило                                                                              |
| --------------- | ------------------------------------------------------------------------------------ |
| Входные форматы | PPTX, PDF и HTML нормализуются в `ContentPack`; шаблон оформления остаётся PPTX      |
| Число вариантов | Пользователь может запросить 1, 2 или 3; evidence matrix и защита всегда проверяют 3 |

## Правило тайминга

Разбор входного контента и нового шаблона является preparation stage без заданного организаторами
лимита. Измеряемая генерация начинается с отправки пользователем запроса и заканчивается только
после готовности всех трёх вариантов, их аудита и обязательных артефактов. Лимит составляет
300 секунд суммарно; параллельное выполнение разрешено.

## Submission checklist

1. Зафиксировать публичный репозиторий либо предоставить экспертам доступ по ссылке.
2. Проверить README из чистого окружения и записать результат.
3. Описать API-провайдера, модели, ревизии и настройки без секретов.
4. Загрузить ссылки на репозиторий, документацию, презентацию, прототип и дополнительные
   материалы заранее.
5. После 29 сентября 2026, 23:59 МСК не менять сданные ветки, связанные документы,
   презентацию, файлы или развернутый прототип.
