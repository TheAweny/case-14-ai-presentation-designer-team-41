# Соответствие требованиям

Этот файл фиксирует обязательные требования кейса и разъяснения модератора. Он отличает целевую
архитектуру от подтверждённой реализации, чтобы команда не выдавала контракт или unit-тест за
готовый конкурсный результат.

Обновление 29 сентября: в `main` работает тривариантный real-model путь с общим планом,
PPTX/PDF/PNG, fit-check/repair, иллюстрациями, индексом шаблонов и persisted API. Редактор
открывает готовую колоду и экспортирует правки в PPTX/PDF/PNG/HTML. Evidence трёх вариантов
(23–35 с на все три, 9 колод на шаблонах организаторов) — в `docs/EVIDENCE.md`; это
технические замеры, не unknown-template holdout и не 3×3 quality gate. Подробные evidence и
нерешённые вопросы — `docs/GENERATION.md`; таблица ниже описывает более широкий конкурсный
gate, а не отсутствие реализации.

## Источники

- техническое задание кейса и материалы организаторов;
- разъяснения модератора в чате задачи от 21–23 сентября 2026;
- критерии сдачи от официального канала от 22–23 сентября 2026.

## Обязательные требования

| Требование                            | Критерий доказательства                                            | Текущий статус                                                                    |
| ------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Незнакомый пользовательский PPTX      | Зафиксированный unknown-template run без ветвлений по шаблону      | Не подтверждено: сценарий `eval/unknown-template.yaml` есть, holdout нет          |
| Три содержательно различимых варианта | Один plan, три стратегии, объяснимые различия                      | Реализовано в `main` (dense/balanced/airy); evidence 2026-09-28                   |
| <= 5 минут на все три варианта        | Замер от пользовательского запроса до готовности всех артефактов   | Измерено: 23–35 с на все три (9 прогонов); holdout-проверка не проведена          |
| Editable PPTX                         | Открытие в PowerPoint/LibreOffice, нативные текст и visuals        | Реализовано: нативный текст, таблицы, графики, картинки; редактор round-trip      |
| PDF и HTML                            | Три формата на каждый вариант, проверки артефактов                 | PDF и PNG на каждый вариант; HTML — страница из PNG-превью, собирается на клиенте |
| Детерминированный аудит               | Findings с rule, evidence и объектом; passing/failing fixtures     | Реализовано: 25 проверок движка + 7 над SlideIR в редакторе                       |
| Контекстный аудит                     | Findings с source refs, confidence и proposal                      | Реализовано: 12 вопросов валидации, per-slide, уверенность в findings             |
| Выборочные исправления                | Пользователь выбирает finding; новый артефакт и re-audit           | Частично: repair-циклы в пайплайне; выбора findings пользователем в UI нет        |
| 3x3 evidence matrix                   | 9 колод, 27 экспортов, без ручного редактирования                  | Частично: 9 колод собраны (см. `docs/EVIDENCE.md`); 27 экспортов не перепроверены |
| Воспроизводимая сдача                 | Public/expert-access repo, README, модели и настройки без секретов | Частично: README и лицензия есть; clean-clone run не подтвержден                  |
| Презентация проекта                   | При применимости: слайды 7–11 сохранены по обязательному шаблону   | Не начато                                                                         |

## Расширение продукта

Следующие возможности добавляются поверх обязательного режима и не уменьшают конкурсный gate:

| Расширение      | Правило                                                                              |
| --------------- | ------------------------------------------------------------------------------------ |
| Входные форматы | PPTX, PDF и HTML нормализуются в `ContentPack`; шаблон оформления остаётся PPTX      |
| Число вариантов | Пользователь может запросить 1, 2 или 3; evidence matrix и защита всегда проверяют 3 |

## Правило тайминга

Разбор входного контента и нового шаблона является preparation stage без заданного организаторами
лимита. Измеряемая генерация начинается с отправки пользователем запроса и заканчивается только
после готовности всех трёх вариантов, их аудита и обязательных артефактов. Лимит составляет
300 секунд суммарно; параллельное выполнение разрешено.
