# Действия агентов в чате

## Поведение

Каждый вызов инструмента показывается отдельным чипом. В нём видны назначение действия,
разрешённые публичные аргументы, состояние и измеренная сервером длительность. Подготовка
аргументов моделью отличается от выполнения инструмента: сетевой запрос ещё не начат,
пока сервер не получил и не проверил аргументы.

Для поиска показывается запрос; для чтения страницы — её адрес; для исследования — вопрос
и вложенные действия. Сырой JSON входов, ответы страниц, заголовки авторизации и другие
служебные данные не выводятся. Неизвестные инструменты сохраняют название и состояние.

Вспомогательная задача агента появляется только при реальном делегировании. Поиск и чтение
страницы — действия инструментов, а не дополнительные агенты. Количество задач агентов
не равно числу одновременно исполняемых запросов модели: задача может ждать внутреннюю
очередь провайдера, а основной агент — ждать результат инструмента.

Индикатор ожидания не изображает процент выполнения. Завершение, ошибка и отмена различимы
по тексту и значку. Движение уменьшается при prefers-reduced-motion. Старые сообщения без
временных меток остаются читаемыми, длительность для них не придумывается.

## Сохранение

Временные метки и вложенные задачи хранятся в метаданных части tool и приходят обычными
событиями part. Это позволяет восстановить те же действия после обновления страницы.
Метаданные не становятся отдельными вызовами инструментов в истории модели.

Вызовы планировщика, писателя, критика и переписчика используют один идентификатор задачи
на логический вызов модели, включая повторные попытки. Три варианта колоды передают события
в один вызов build_deck; инструмент с подключённой телеметрией ожидает завершения всех вариантов,
чтобы не объявить ещё выполняющиеся задачи отменёнными после готовности первого варианта.
События провайдера не содержат промптов, ответов модели и настроек подключения.

История вложенных действий ограничена последними 32 записями одного вызова. При достижении
границы можно удалить старую завершённую запись; активные задачи и их завершение сохраняются.
Закрытая задача не возобновляется от запоздавшего события. Завершённое сообщение не показывает
оставшиеся в старой истории running-задачи как активные.

## Приёмка

- Поиск, чтение страницы и делегированный исследователь видны до окончания родительского вызова.
- Итоговый ответ сохраняет вложенные задачи; попадание в кэш не изображает новый сетевой запрос.
- Отмена или ошибка закрывает начатые действия; ошибка карточного инструмента не пропадает.
- Данные старого чата читаются без миграции. Счётчик не считает инструменты агентами.
- Длинные запросы и адреса не расширяют экран; публичные детали доступны с клавиатуры.
- Изображения, загруженные через редактор, и панель управления источниками относятся к отдельному
  следующему этапу; эти чипы не означают готовность их сквозной интеграции.

## Образец взаимодействия

Визуальный ориентир — [React Bits Call Chip](https://reactbits.dev/c/micro/call-chip).
Реализация использует существующие компоненты, значки и motion/react проекта.

## Проверки серверного среза

- Контракты: 286 тестов; pipeline: 361 тест; API: 353 теста, включая ожидание всех вариантов
  дольше прежнего grace. Все эти наборы выполнены без сети и живой модели.
- Независимые сценарии проверяют последовательность поиск → чтение → исследователь,
  отсутствие фиктивного запроса при попадании в кэш, передачу событий порциями UTF-8,
  отмену, игнорирование позднего сбоя уже выполненной задачи и историю длиннее 32 действий.
- Отдельно проверены параллельные вызовы общего провайдера и сохранение идентификатора
  при 429. Ошибка слушателя телеметрии не меняет ответ модели или инструмента.
- В пересобранном API-контейнере отдельно прогнан скомпилированный dispatcher: три вложенных
  шага исследования, один агент и их переходы к done прошли валидацию сохранённого сообщения.
- Веб: typecheck и lint; 34 проверки потока событий, представления действий, восстановления
  чата и повтора. Двенадцать браузерных сценариев прошли в Chrome, включая desktop,
  мобильный экран, reduced motion, перезагрузку, ошибки и сохранение прежних переходов сборки.
  Финальные сценарии также проверяют отсутствие ошибок перевода и выполнения JavaScript.
- Скриншоты desktop и мобильного экрана просмотрены. Проверка Impeccable не нашла нарушений
  в изменённых компонентах. Автоматические сценарии используют фикстуры, а не живую модель.
