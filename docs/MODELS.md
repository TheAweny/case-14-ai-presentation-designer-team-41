# Модели

Каталог моделей живёт в `configs/models.yaml`: прогон ссылается на записи по id, а манифест
прогона фиксирует разрешённую ревизию, чтобы колоду можно было связать с конкретными весами.

Все обращения к моделям происходят на стороне TypeScript, в `packages/pipeline`. Движок моделей
не вызывает вообще — это позволяет прогонять его тесты без GPU и без сети.

## Роли в пайплайне

| Роль      | Что делает                                                                  | Тип модели    |
| --------- | --------------------------------------------------------------------------- | ------------- |
| `planner` | строит план колоды: о чём каждый слайд и какой у него тип                   | LLM           |
| `writer`  | пишет тексты слайдов и переписывает их по сигналам о переполнении           | LLM           |
| `critic`  | контекстные проверки аудита и формулировка правок                           | LLM           |
| `vision`  | смотрит на отрендеренные слайды: композиция, читаемость, соответствие стилю | VLM           |
| `image`   | иллюстрации, когда контент-пак их не даёт                                   | text-to-image |

## Каталог

Каталог проверяется контрактом `ModelCatalog` из `packages/contracts` при загрузке: веса только
открытые, лицензия Apache-2.0 или MIT, не больше 35B параметров, ревизия закреплена коммитом.
Каталог с нарушением просто не загрузится.

| id                    | Назначение                                 | Hugging Face                                                                                | Ревизия    | Лицензия   | Размер             |
| --------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------- | ---------- | ---------- | ------------------ |
| `planner-default`     | план колоды                                | [Qwen/Qwen3-30B-A3B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507) | `0d7cf239` | Apache-2.0 | 30.5B, 3B активных |
| `writer-default`      | тексты слайдов, сокращение по overflow     | та же                                                                                       | `0d7cf239` | Apache-2.0 | 30.5B, 3B активных |
| `critic-default`      | контекстный аудит                          | та же                                                                                       | `0d7cf239` | Apache-2.0 | 30.5B, 3B активных |
| `vision-default`      | вопросы валидации по картинке слайда       | [Qwen/Qwen3-VL-8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct)               | `0c351dd0` | Apache-2.0 | 8.8B               |
| `vision-large`        | то же, где позволяет бюджет                | [Qwen/Qwen3-VL-32B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-32B-Instruct)             | `0cfaf481` | Apache-2.0 | 33.4B              |
| `illustrator-default` | иллюстрации (задача со звёздочкой)         | [black-forest-labs/FLUX.1-schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell) | `741f7c3c` | Apache-2.0 | 12B                |
| `fake`                | записанные ответы для тестов и офлайн-демо | нет весов, ответы в `registry/recordings/`                                                  | `v1`       | Apache-2.0 | нет                |

Почему MoE-модель для текстовых ролей: при 3B активных параметров на токен колода на 10–15
слайдов укладывается в бюджет 5 минут на одной GPU или на внешнем endpoint, а качество у неё на
уровне плотных моделей 30B.

## Как модель вызывается

- Провайдер `openai-compatible` говорит с любым рантаймом с OpenAI chat API: vLLM, llama.cpp,
  SGLang или внешний провайдер моделей с открытыми весами. Адрес берётся из переменной
  `baseUrlEnv` записи каталога, ключ из `MODEL_API_KEY`, имя модели из `servedName` или `repo`.
- Инструкция агента из `registry/agents/<id>/instructions.md` уходит системным сообщением, вход
  шага пользовательским сообщением в JSON, параметры генерации из `agent.yaml`, seed прогона.
- Ответ обязан быть JSON схемы `outputSchema` агента. Невалидный ответ отправляется модели
  обратно один раз вместе с ошибкой валидации, после второй неудачи шаг падает: ограниченный
  повтор держит прогон в бюджете времени.
- `MODEL_PROVIDER=fake` отвечает записанными ответами, без сети и GPU: так работают тесты и
  офлайн-демо. `MODEL_PROVIDER=record` вызывает настоящую модель и записывает ответы.

## Требования к выбору весов

- **Лицензия.** Веса берём только под лицензиями, которые допускают коммерческое использование:
  та же политика, что и для зависимостей (см. `docs/LICENSES.md`). Лицензия каждой записи
  указывается в `configs/models.yaml` и попадает в эту таблицу.
- **Ревизия.** В конфиге фиксируется коммит или тег, а не `main`: иначе прогон перестаёт быть
  воспроизводимым.
- **Доступ.** Модели обслуживаются рантаймом с OpenAI-совместимым API, адрес берётся из
  переменной окружения, указанной в поле `baseUrlEnv`. Ключи в репозиторий не попадают.
- **Веса в репозиторий не коммитятся.** В нём есть только ссылки и ревизии.

## Системные требования

Раздел заполняется после замеров: сюда приходят требования по видеопамяти и по времени ответа на
слайд, из которых складывается бюджет в 5 минут на колоду.
