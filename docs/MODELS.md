# Модели

Каталог моделей живёт в `configs/models.yaml`: прогон ссылается на записи по id, а манифест
прогона фиксирует разрешённую ревизию, чтобы колоду можно было связать с конкретными весами.

Все обращения к моделям происходят на стороне TypeScript, в `packages/pipeline`. Движок моделей
не вызывает вообще — это позволяет прогонять его тесты без GPU и без сети.

## Активное подключение

Текстовые роли читают `planner-default`, `writer-default` и `critic-default`: это
Qwen3-30B-A3B-Instruct-2507, 30.5B параметров и около 3.3B активных на токен. Картинки слайдов
читает `vision-default`, Qwen3-VL-8B-Instruct, 8.8B. Обе модели открытые, Apache-2.0, и обе ниже
потолка кейса в 35B. Qwen3.6-35B-A3B (около 35.95B по metadata весов) в каталоге нет: базовый
инстанс Yandex AI Studio отдаёт именно её под именем `qwen3.6-35b-a3b`, поэтому этот URI в
`.env` ставить нельзя.

**Демостенд** (https://lct-demo.awenylab.com, 2026-09-29) работает на `qwen3.6-35b-a3b` из Yandex
AI Studio для всех текстовых ролей. Qwen3-30B-A3B-Instruct-2507 в AI Studio нет, а единственная
меньшая открытая модель там, `gpt-oss-20b` (Apache-2.0, 21B), на проверке собрала три варианта
за 5 мин 20 с, за пределами бюджета; Qwen3.6-35B-A3B укладывается в 3 минуты. Модель —
Apache-2.0, её класс по названию — 35B (по metadata весов 35.95B, см. «Потолок 35B»).
Иллюстрации на стенде выключены: ни одна доступная нам модель изображений не открытая; роль
«Иллюстратор» подключается в настройках любой OpenAI-совместимой text-to-image моделью.

Endpoint и имя модели задаются только окружением:

- `LLM_BASE_URL` — OpenAI-совместимый runtime с весами `Qwen/Qwen3-30B-A3B-Instruct-2507`;
- `LLM_MODEL` — имя, под которым runtime их отдаёт; пустое значение значит имя репозитория из каталога;
- `VLM_BASE_URL` и `VLM_MODEL` — то же для `Qwen/Qwen3-VL-8B-Instruct`;
- `MODEL_API_KEY` — секрет в локальном `.env`, заголовок `Authorization: Bearer ...`.
- `MODEL_HEADERS` — заголовки, которые runtime требует кроме ключа, парами `Имя=значение` через
  запятую. Подключения из интерфейса задают их полем «Заголовки». Ключ туда не пишут.

API и CLI используют один `OpenAICompatibleProvider`; автоматического переключения на
OpenRouter или другую модель нет.

**Что умеет каждая модель.** По имени модели ничего не решается: имя выбирает провайдер. Модели
тоже не проверяются платными запросами: при сотне моделей это долго и дорого (одна такая проверка
четырёх моделей zapro стоила около 4 долларов). Тип модели берётся из того, что провайдер сам
пишет о моделях в ответе `/models`, который и так запрашивается при проверке подключения
(`apps/api/src/models/model-details.ts`):

- VK AI Space: `model_type` (`llm`, `vlm`, `stt`, `embedding`, `reranker`), `tasks`,
  `input_modalities`, теги `thinking-mode` и `reasoning`;
- OpenRouter: `architecture.input_modalities` / `output_modalities`, `supported_parameters`;
- шлюзы на new-api (po.zapro.su): `supported_endpoint_types` (`image-generation`, `video`…);
- LiteLLM и другие: `mode`, `type`, `capabilities`.

Описание хранится вместе с итогом проверки подключения (`lastCheck.details`). Модель, о которой
провайдер ничего не сказал, считается текстовой, которая может видеть картинки. В настройках
подключения («Модели») у каждой модели можно вручную задать тип: текст, текст и картинки,
изображения, голос или «не используется». Ручной выбор главнее описания и действует для всех,
кто пользуется этим подключением (таблица `model_connection_capabilities`, поле `manual_kinds`).
Находки хранятся по подключению и его адресу, а не по одному адресу: личное подключение к тому же
серверу, что и общее, не меняет того, что видят остальные. Тип вроде `"model"` у Anthropic или
`"base"` у Mistral ничего не говорит о модели, и она считается неописанной. Каждый выбор
модели для роли предлагает только модели нужного типа. Голосовой ввод сам берёт первую модель
голоса, если роли «Расшифровка голоса» не назначено другое.

**Размышление и глубина.** Тоже из описания: `thinking-mode` даёт выключатель через
`enable_thinking`, параметр `reasoning` или `reasoning_effort` даёт глубину. Если описание
молчит, при добавлении и проверке подключения каждой текстовой модели отправляется один запрос с
несуществующим значением `reasoning_effort` и `max_tokens: 1`. Сервер, который читает поле,
отклоняет такой запрос ещё до вызова модели, и это бесплатно. Тогда модель получает глубину, а
выключатель (`none`) — только если `none` есть среди перечисленных в отказе значений: o3, GPT-5 и
vLLM (он проверяет поле у любой модели) такое значение не принимают. Сервер, который поле
отбрасывает, отвечает одним токеном. Результат хранится в `model_connection_capabilities` до
следующей проверки подключения. Работает ли глубина на самой модели, так не узнать: это видно
только по платным ответам. Чат думает всегда, когда модель это позволяет: так задано в конфиге
ассистента (`generation.thinking` в `registry/agents/chat-assistant/agent.yaml`), из интерфейса
это не меняется. Переключатель «Думать при сборке» в композере относится только к сборке колоды.
Он по умолчанию выключен. Включённый, он даёт сборке на 8192 токена больше и до 180 с на ответ
вместо 65 с. Пока модель
думает через `reasoning_effort`, запрос уходит без `temperature` и `top_p`: reasoning-модели их не
принимают. Прежняя политика по имени (`Qwen3`, `Qwen3.8`,
`-Thinking-`, регистр и алиас вроде `qwen38-27b-fp8`) заменена этими метаданными и пробой:
клиент не выключает размышление по имени модели. Поля `reasoning` и `probed` остаются в ответе и не
обнуляются: нет выбора — это `{ toggle: null, levels: false }`, а не отсутствующий объект. Выключенный `enable-thinking` не дополняется `reasoning_effort`. Генерация передаёт
`response_format` типа `json_schema` со строгой схемой из Zod, ответ дополнительно валидируется
локально. Блоки размышления не попадают в ответ пользователю.

Общая квота каталога, сообщённая командой, — 10 одновременных запросов. Приложение занимает
`MODEL_MAX_CONCURRENCY` (по умолчанию 8) HTTP-слотов **на процесс**, совместно для всех прогонов;
трём вариантам одной генерации этого хватает, чтобы идти параллельно. CLI и несколько API replicas
имеют независимые лимитеры: параллельные процессы необходимо учитывать при распределении
общей квоты. При 429/502/503 запрос повторяется до пяти раз с экспоненциальной паузой (1, 2, 4,
8, 16 с) с джиттером и не короче `Retry-After`. После 429 или 503 лимитер вдвое сокращает число
слотов и придерживает новые запросы на время паузы, затем возвращает по слоту за серию
ответов; ожидание очереди и backoff прерываются общим сигналом отмены/deadline. Ключи и тела
ошибок провайдера не включаются в сообщения ошибок приложения.

**VK AI Space (финал, 2026-10-16).** Финалисты работают на модели `qwen38-27b-fp8` (Qwen 3.8 27B,
FP8) через OpenAI-совместимый шлюз VK. Кроме ключа шлюз требует заголовок `Project-ID`:

```
LLM_BASE_URL=https://ai-demo.platformpreview.ru/api/inference-providers-router/00000000-0000-0000-0000-000000000001/v1
LLM_MODEL=qwen38-27b-fp8
MODEL_API_KEY=<ключ из письма организаторов>
MODEL_HEADERS=Project-ID=<id проекта>
```

Быстрее всего подключить VK мастером: `lct onboard` → «VK AI Space», затем API-ключ и Project ID
(без вопросов: `--provider vk --api-key … --project-id …`). В интерфейсе то же делает пресет
«VK AI Space» в «Настройки → Модели»: после сохранения модель сама назначается ассистенту,
планировщику, автору текстов, критику и зрению. Подключение из `.env` отдаёт зрение той же
модели, когда `VLM_BASE_URL` совпадает с `LLM_BASE_URL`.

Что проверено на шлюзе: модель принимает картинки (VLM, контекст 210 тыс. токенов), вызывает
инструменты, отключает размышления, выдаёт около 60 токенов в секунду. Строгую схему
`response_format` она принимает, но не соблюдает. Поэтому провайдер генерации кладёт JSON-схему
ответа ещё и в инструкцию (`registry/shared/answer-format.md`), а ответ не по схеме один раз
возвращает модели с перечнем ошибок (`registry/shared/answer-repair.md`). Квота проекта —
10 000 запросов; одна сборка из трёх вариантов тратит около 90.

Замер 2026-10-16, бриф с цифрами на 10 слайдов, три варианта параллельно: шаблон VK Tech — 202 с,
VK WorkSpace — 148 с, собраны все шесть вариантов. Исправлять ответ пришлось один раз на 183
запроса, ответов 429 не было. Ревизия весов `qwen38-27b-fp8` организаторами не опубликована,
поэтому в `configs/models.yaml` её пока нет.

## Подключения из интерфейса и ключи

В интерфейсе `writer` называется «Основная модель». Назначения ассистента, планировщика и
критика находятся в свёрнутых расширенных настройках: без своей модели они используют
основную. Явный вариант «Использовать основную» (`kind: default`) также заменяет отдельное
назначение администратора для текущего пользователя. Снятие назначения возвращает общие
настройки. Анализ и генерация изображений настраиваются отдельно.

Выбор в чате хранится в `chats.model`, действует на этот разговор и переживает перезагрузку.
Умолчание чата — `assistant`, затем основная модель. Явные роли планировщика и критика
сохраняют приоритет при сборке; меню показывает их. Выключенная или удалённая модель
не подменяется другой автоматически. Восстановление после ошибок описано в
[CHAT_INTERACTIONS.md](CHAT_INTERACTIONS.md).

Список моделей общий для чата и назначения ролей: производители, поиск и группы подключений
показываются одним `ModelList`. Роль ограничивает список по возможностям модели. Каталог
объединяет найденные провайдером модели, явно включённые идентификаторы, ручные категории и
модели назначенных ролей. Неуспешная проверка `/models` не скрывает явно добавленные модели;
ограничение включённых идентификаторов продолжает действовать. Личные подключения
администратора доступны ему наравне с общими. Окно настроек и поля ввода читают один снимок
настроек текущего аккаунта.

Кроме подключения из `.env`, модели подключают в интерфейсе («Настройки → Модели»). Прогон
получает от браузера только выбор `{connectionId, modelId}`; модель берётся так: выбранная у поля
ввода, иначе модель роли `writer`, иначе подключение из `.env`. Нет ни одной — API не создаёт
прогон и отвечает 503 с понятной причиной.

- **Подключение из `.env`** видно в интерфейсе как встроенное (`connectionId: server`): его можно
  проверить, но не изменить и не удалить. Ключ правят в `.env`, в браузер уходят только признак
  ключа и его последние четыре символа.
- **Ключи подключений из интерфейса** хранит API в Postgres (`model_connections`) только
  шифротекстом AES-256-GCM. Ключ шифрования выводится из `MODEL_KEYS_SECRET`, который
  `lct onboard` генерирует один раз на установку; id подключения входит в аутентифицированные
  данные, так что шифротекст, перенесённый в другую строку, не расшифруется. Без секрета ключ не
  сохраняется совсем. Ключ, который перестал расшифровываться, интерфейс показывает как
  незаданный — его вводят заново.
- **Ни один ответ API не содержит ключа**: наружу уходит только публичный вид подключения
  (`modelConnectionSchema`), в журнал `model_settings_events` — кто и что изменил, без ключа.
- **API отвечает только веб-серверу**: запрос без `API_SERVICE_TOKEN` получает 403, открыт только
  `/health`. Настройки моделей доступны лишь серверным действиям веба; прокси `/api/backend` для
  браузера их не пропускает.
- **Адрес, куда API идёт с ключом**, проверяется: редиректы запрещены (`redirect: 'error'`), чтобы
  ключ не ушёл на чужой хост, а адреса внутренних сетей (loopback, 10/8, 172.16/12, 192.168/16,
  169.254/16, ULA IPv6) запрещены, пока `MODEL_ALLOW_PRIVATE_HOSTS` не равен `true`. Имя хоста
  сначала разрешается, так что публичное имя с частным адресом тоже ловится. Подключение из `.env`
  задаёт администратор, на него запрет не распространяется.

Список у поля ввода можно сузить по семейству, а в выборе модели для роли длинный список
подключения разложен по семействам подменю. Семейство читается из id модели по обычному
имени (GPT, Claude, Gemini, Qwen, Llama, DeepSeek, Mistral, Grok, Command, Phi, Gemma, Yi),
а не по возможностям: проверка подключения отдаёт только id. Префикс протокола семейством
не считается, поэтому `gpt://.../qwen3` остаётся Qwen.

У подключения можно оставить только часть найденных моделей (меню подключения → «Модели»,
там же «Включить все» и «Выключить все» — для всего списка или для отфильтрованного).
Выключение — свойство подключения, а не аккаунта: у общего подключения и подключения из
`.env` оно действует для всех, кто пользуется этим ключом, и меняет его только
администратор. Выключенная модель пропадает из выбора у поля ввода и у ролей, а сервер
отклоняет прогон с ней. Пока ничего не выключено, доступна любая модель, и новые тоже;
как только часть выключена, доступны только включённые — вписать id вручную у такого
подключения нельзя, иначе так обходили бы запрет. Неудачная проверка список не сбрасывает.
Список подключения из `.env` хранится в базе по его адресу, поэтому переживает перезапуск,
а другой адрес в `.env` начинает без ограничений.

Иллюстрации рисует роль `image` через OpenAI-совместимый `POST /images/generations`
(`OpenAICompatibleImageProvider`): просит `b64_json`, принимает и `url`, повторяет при 429, 502,
503 и обрыве сети, одна картинка ждёт не дольше 90 с. Картинки идут через свой пул
(`IMAGE_MAX_CONCURRENCY`, по умолчанию 3) и не занимают слоты текстовой модели. Промпт пишет
агент `illustrator` на модели писателя. Порядок выбора модели и запасной путь без неё описаны
в `docs/GENERATION.md`, раздел «Иллюстрации».

`latest` — изменяемый provider alias, а не зафиксированный commit весов. Манифест честно
указывает `hosted-revision-not-reported`; hash URI не является checksum весов.

Проверка 2026-09-27: обычный текст и строгий JSON вернули HTTP 200 за 0.81 и 0.21 секунды.
Живой Mastra workflow (план + два writer-запроса) завершился за 1056 мс. Evidence без секретов:
`runs/provider-check/yandex-result.json`. Это небольшой smoke-тест, не доказательство
готовности PPTX или выполнения полного пяти-минутного SLA.

## Роли в пайплайне

Роль в прогоне исполняет агент из `registry/agents/` (id в конфиге агента). У каждого агента
своя версия semver, свой `instructions.md` и своя модель по умолчанию.

| Роль        | Агент (id)                          | Что делает                                                                   | Тип модели |
| ----------- | ----------------------------------- | ---------------------------------------------------------------------------- | ---------- |
| `assistant` | `chat-assistant`                    | ведёт чат: отвечает, вызывает инструменты, предлагает план, запускает сборку | LLM        |
| `planner`   | `deck-planner`                      | строит план колоды: о чём каждый слайд и какая композиция                    | LLM        |
| `indexer`   | `template-indexer`                  | описывает композиции шаблона при подготовке (вне timed-бюджета)              | LLM        |
| `writer`    | `slide-writer`                      | пишет тексты слайдов под выбранные композиции                                | LLM        |
| `writer`    | `copy-fitter`, `slot-rewriter`      | укорачивают не влезший текст, предлагают законченные варианты                | LLM        |
| `critic`    | `deck-critic`                       | контекстные проверки аудита и формулировка правок                            | LLM        |
| `vision`    | `slide-reviewer`                    | отвечает на вопросы валидации контента по каждому слайду                     | VLM        |
| `image`     | `illustrator` (промпт) + image-роль | иллюстрации: промпт пишет текстовая модель, картинку — text-to-image         | LLM + TTI  |

Параметры каждой роли (модель, температура, лимит токенов, схема ответа) — в
`registry/agents/<id>/agent.yaml`. Планировщик, писатель и критик — роли одной текстовой
модели; набор ролей описан в `docs/GENERATION.md`.

## Каталог

Каталог проверяется контрактом `ModelCatalog` из `packages/contracts` при загрузке: веса только
открытые, лицензия Apache-2.0 или MIT, не больше 35B параметров, ревизия закреплена коммитом.
Каталог с нарушением просто не загрузится.

Почему MoE для текстовых ролей: 30.5B всего и около 3.3B активных на токен. Колода на 10–15
слайдов остаётся в бюджете 5 минут, и полный размер не переступает потолок кейса в 35B.

## Как модель вызывается

- Провайдер `openai-compatible` говорит с любым рантаймом с OpenAI chat API: vLLM, llama.cpp,
  SGLang или внешний провайдер моделей с открытыми весами. Адрес берётся из переменной
  `baseUrlEnv` записи каталога, ключ из `MODEL_API_KEY`, имя модели из `servedName` или `repo`.
- Инструкция агента из `registry/agents/<id>/instructions.md` уходит системным сообщением, вход
  шага пользовательским сообщением в JSON, параметры генерации из `agent.yaml`, seed прогона.
- Ответ обязан быть JSON схемы `outputSchema` агента. Невалидный ответ отправляется модели
  обратно один раз вместе с ошибкой валидации, после второй неудачи шаг падает: ограниченный
  повтор держит прогон в бюджете времени.
- `MODEL_PROVIDER=fake` отвечает записанными ответами, без сети и GPU: так работают тесты и
  офлайн-демо. `MODEL_PROVIDER=record` вызывает настоящую модель и записывает ответы.

## Требования к выбору весов

- **Лицензия.** Веса берём только под лицензиями, которые допускают коммерческое использование:
  та же политика, что и для зависимостей (см. `docs/LICENSES.md`). Лицензия каждой записи
  указывается в `configs/models.yaml` и попадает в эту таблицу.
- **Ревизия.** В конфиге фиксируется коммит или тег, а не `main`: иначе прогон перестаёт быть
  воспроизводимым.
- **Доступ.** Модели обслуживаются рантаймом с OpenAI-совместимым API, адрес берётся из
  переменной окружения, указанной в поле `baseUrlEnv`. Ключи в репозиторий не попадают.
- **Веса в репозиторий не коммитятся.** В нём есть только ссылки и ревизии.

## Потолок 35B

Кейс разрешает открытые веса не больше 35B параметров. Qwen3.6-35B-A3B по metadata содержит
35 951 822 704 параметра, около 35.95B, поэтому каталог на неё не ссылается. Текстовые роли
сидят на Qwen3-30B-A3B-Instruct-2507 (safetensors: 30 532 122 624, 30.5B), ревизия
`0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe`. Зрение — Qwen3-VL-8B-Instruct (8 767 123 696, 8.8B),
ревизия `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`. Иллюстрации рисует роль `image`, см. выше.

## Согласование возможностей провайдера

Текстовые вызовы чата, генератора и каталога используют общий адаптер
`packages/pipeline/src/models/compatibility.ts`. Он не угадывает возможности по имени
модели и не заменяет выбранную модель другой.

- При явном отказе `json_schema` запрос повторяется как `json_object`; если сервер
  явно отклоняет и его, запрос идёт без `response_format`. Исходная схема остаётся
  в инструкциях и локальной Zod-валидации. В частности, `sourceEvidence` сохраняет
  произвольные ключи: транспортный fallback не меняет контракт и не теряет факты.
- Только явно отклонённые `seed`, `temperature`, `top_p` убираются из запроса;
  `max_tokens` может замениться на `max_completion_tokens` с тем же лимитом.
  Запрошенные thinking/effort не отбрасываются молча: несовместимое значение
  возвращает ошибку с безопасным именем параметра.
- Отказ streaming позволяет получить полный ответ. Нестандартный SSE без индексов
  вызовов или `[DONE]` не разрешает действия сам по себе: клиент один раз повторяет
  запрос без streaming и проверяет новый ответ. Предварительный текст в чате
  заменяется проверенным, а не дублируется. Настоящий сетевой обрыв и повреждённые
  события по-прежнему блокируют инструменты.
- Согласование ограничено числом попыток и deadline; 401/403, перегрузка и
  произвольные ошибки запроса не означают отказ возможностей. Особенности
  запоминаются внутри экземпляра адаптера, без общего кеша между аккаунтами.
- Ошибки сохраняют HTTP status и безопасное имя отклонённого параметра, но не
  произвольное тело ответа сервера. Протокольная несовместимость в чате не
  классифицируется как физическая недоступность модели.

Поддерживаемый интерфейс — OpenAI-совместимый `/chat/completions`, не произвольный
нативный API любого поставщика. Формальная совместимость не гарантирует качество
содержания, наличие квоты или поддержку неподходящей для модели модальности.
Требования и приёмка: [provider-compatibility.md](../spec/provider-compatibility.md).

Проверка 2026-10-18: реальный чат с `qwen38-27b-fp8` и `gpt-6.1-sol`
завершился после вызова `list_templates`. На GPT собраны все три варианта по
10 слайдов за 281,3 с; PPTX/PDF скачаны через API, их SHA-256 совпали с manifest,
PPTX повторно открыт Python-движком, у каждого PDF 10 страниц. Это измерение
