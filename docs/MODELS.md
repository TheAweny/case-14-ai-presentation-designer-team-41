# Модели

Каталог моделей живёт в `configs/models.yaml`: прогон ссылается на записи по id, а манифест
прогона фиксирует разрешённую ревизию, чтобы колоду можно было связать с конкретными весами.

Все обращения к моделям происходят на стороне TypeScript, в `packages/pipeline`. Движок моделей
не вызывает вообще — это позволяет прогонять его тесты без GPU и без сети.

## Активное подключение: Yandex AI Studio

С 27 сентября 2026 текстовый workflow использует одну модель через OpenAI-совместимый
Chat Completions API. `deck-planner` и `slide-writer` ссылаются на `qwen-yandex`.
Конкретный endpoint и model URI задаются только окружением:

- `LLM_BASE_URL=https://llm.api.cloud.yandex.net/v1`;
- `LLM_MODEL=gpt://<folder-id>/qwen3.6-35b-a3b/latest`;
- `MODEL_API_KEY` — секрет в локальном `.env`, заголовок `Authorization: Bearer ...`.

API и CLI используют один `OpenAICompatibleProvider`; автоматического переключения на
OpenRouter или другую модель нет. Каждый запрос передаёт
`chat_template_kwargs: { enable_thinking: false }` и `response_format` типа `json_schema`
со строгой схемой, полученной из Zod. Ответ дополнительно валидируется локально.

Общая квота каталога, сообщённая командой, — 10 одновременных запросов. Приложение занимает
не более 3 HTTP-слотов **на процесс**, совместно для всех прогонов. CLI и несколько API replicas
имеют независимые лимитеры: параллельные процессы необходимо учитывать при распределении
общей квоты. При 429/502/503 разрешены максимум две повторные попытки с backoff; ожидание
очереди и backoff прерываются общим сигналом отмены/deadline. Ключи и тела ошибок провайдера
не включаются в сообщения ошибок приложения.

## Подключения из интерфейса и ключи

Кроме подключения из `.env`, модели подключают в интерфейсе («Настройки → Модели»). Прогон
получает от браузера только выбор `{connectionId, modelId}`; модель берётся так: выбранная у поля
ввода, иначе модель роли `writer`, иначе подключение из `.env`. Нет ни одной — API не создаёт
прогон и отвечает 503 с понятной причиной.

- **Подключение из `.env`** видно в интерфейсе как встроенное (`connectionId: server`): его можно
  проверить, но не изменить и не удалить. Ключ правят в `.env`, в браузер уходят только признак
  ключа и его последние четыре символа.
- **Ключи подключений из интерфейса** хранит API в Postgres (`model_connections`) только
  шифротекстом AES-256-GCM. Ключ шифрования выводится из `MODEL_KEYS_SECRET`, который
  `lct onboard` генерирует один раз на установку; id подключения входит в аутентифицированные
  данные, так что шифротекст, перенесённый в другую строку, не расшифруется. Без секрета ключ не
  сохраняется совсем. Ключ, который перестал расшифровываться, интерфейс показывает как
  незаданный — его вводят заново.
- **Ни один ответ API не содержит ключа**: наружу уходит только публичный вид подключения
  (`modelConnectionSchema`), в журнал `model_settings_events` — кто и что изменил, без ключа.
- **API отвечает только веб-серверу**: запрос без `API_SERVICE_TOKEN` получает 403, открыт только
  `/health`. Настройки моделей доступны лишь серверным действиям веба; прокси `/api/backend` для
  браузера их не пропускает.
- **Адрес, куда API идёт с ключом**, проверяется: редиректы запрещены (`redirect: 'error'`), чтобы
  ключ не ушёл на чужой хост, а адреса внутренних сетей (loopback, 10/8, 172.16/12, 192.168/16,
  169.254/16, ULA IPv6) запрещены, пока `MODEL_ALLOW_PRIVATE_HOSTS` не равен `true`. Имя хоста
  сначала разрешается, так что публичное имя с частным адресом тоже ловится. Подключение из `.env`
  задаёт администратор, на него запрет не распространяется.

Иллюстрации по-прежнему mocked: в `images.json` записываются запросы со статусом
`not-generated`, вызовов image API нет. Вход изображений в текстовую модель этим этапом
не проверялся и не подключался.

`latest` — изменяемый provider alias, а не зафиксированный commit весов. Манифест честно
указывает `hosted-revision-not-reported`; hash URI не является checksum весов.

Проверка 2026-09-27: обычный текст и строгий JSON вернули HTTP 200 за 0.81 и 0.21 секунды.
Живой Mastra workflow (план + два writer-запроса) завершился за 1056 мс. Evidence без секретов:
`runs/provider-check/yandex-result.json`. Это небольшой smoke-тест, не доказательство
готовности PPTX или выполнения полного пяти-минутного SLA.

## Роли в пайплайне

| Роль      | Что делает                                                                  | Тип модели    |
| --------- | --------------------------------------------------------------------------- | ------------- |
| `planner` | строит план колоды: о чём каждый слайд и какой у него тип                   | LLM           |
| `writer`  | пишет тексты слайдов и переписывает их по сигналам о переполнении           | LLM           |
| `critic`  | контекстные проверки аудита и формулировка правок                           | LLM           |
| `vision`  | смотрит на отрендеренные слайды: композиция, читаемость, соответствие стилю | VLM           |
| `image`   | иллюстрации, когда контент-пак их не даёт                                   | text-to-image |

## Каталог

Каталог проверяется контрактом `ModelCatalog` из `packages/contracts` при загрузке: веса только
открытые, лицензия Apache-2.0 или MIT, не больше 35B параметров, ревизия закреплена коммитом.
Каталог с нарушением просто не загрузится.

Почему MoE-модель для текстовых ролей: при 3B активных параметров на токен колода на 10–15
слайдов укладывается в бюджет 5 минут на одной GPU или на внешнем endpoint, а качество у неё на
уровне плотных моделей 30B.

## Как модель вызывается

- Провайдер `openai-compatible` говорит с любым рантаймом с OpenAI chat API: vLLM, llama.cpp,
  SGLang или внешний провайдер моделей с открытыми весами. Адрес берётся из переменной
  `baseUrlEnv` записи каталога, ключ из `MODEL_API_KEY`, имя модели из `servedName` или `repo`.
- Инструкция агента из `registry/agents/<id>/instructions.md` уходит системным сообщением, вход
  шага пользовательским сообщением в JSON, параметры генерации из `agent.yaml`, seed прогона.
- Ответ обязан быть JSON схемы `outputSchema` агента. Невалидный ответ отправляется модели
  обратно один раз вместе с ошибкой валидации, после второй неудачи шаг падает: ограниченный
  повтор держит прогон в бюджете времени.
- `MODEL_PROVIDER=fake` отвечает записанными ответами, без сети и GPU: так работают тесты и
  офлайн-демо. `MODEL_PROVIDER=record` вызывает настоящую модель и записывает ответы.

## Требования к выбору весов

- **Лицензия.** Веса берём только под лицензиями, которые допускают коммерческое использование:
  та же политика, что и для зависимостей (см. `docs/LICENSES.md`). Лицензия каждой записи
  указывается в `configs/models.yaml` и попадает в эту таблицу.
- **Ревизия.** В конфиге фиксируется коммит или тег, а не `main`: иначе прогон перестаёт быть
  воспроизводимым.
- **Доступ.** Модели обслуживаются рантаймом с OpenAI-совместимым API, адрес берётся из
  переменной окружения, указанной в поле `baseUrlEnv`. Ключи в репозиторий не попадают.
- **Веса в репозиторий не коммитятся.** В нём есть только ссылки и ревизии.

## Системные требования

Раздел заполняется после замеров: сюда приходят требования по видеопамяти и по времени ответа на
слайд, из которых складывается общий бюджет в 5 минут на генерацию всех трёх вариантов после
отправки пользователем запроса. Анализ шаблона и входного контента измеряется отдельно как
подготовительный этап.

## Согласованное исключение по размеру (2026-09-27)

Для Qwen3.6-35B-A3B metadata весов указывает 35,951,822,704 параметра (около 35.95B),
а не строго <=35B. Пользователь явно разрешил продолжать с этой предоставленной моделью.
`configs/models.yaml` отражает полный размер. Это проектное исключение, не утверждение
соответствия строгому конкурсному порогу. Указанная лицензия — Apache-2.0; metadata revision
`995ad96eacd98c81ed38be0c5b274b04031597b0` не доказывает ревизию обслуживаемого Yandex alias.
Все четыре роли single-deck workflow используют этот endpoint. Для иллюстраций вызовов нет.
