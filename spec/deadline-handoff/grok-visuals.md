# Grok: изображения, самостоятельные композиции и достоверный экспорт

Это самостоятельное задание на реализацию, а не запрос нового плана. Репозиторий:
https://github.com/TheAweny/case-14-ai-presentation-designer-team-41.
Начинай от актуальной ветки `theaweny/generation-deadline-integration`, если она ещё не в main;
если уже в main — от main. Выполни fetch, проверь ancestry и рабочее дерево. Не основывай работу
на старой content-quality-variants. Создай свою короткую ветку `theaweny/grok-visual-quality`.
Commit, push своей ветки и PR разрешены. Production deploy и merge в main — отдельное решение.
Никакие локальные файлы координатора или прошлые чаты не требуются.

## Результат

Три пригодные для показа презентации на пользовательском, в том числе незнакомом шаблоне.
Различия должны быть видны в композиции и подаче; изменение только кегля недостаточно.
Все факты, порядок слайдов, числа, единицы и условия остаются общими, формулировки и глубина
различаются согласно dense/balanced/airy. KPI, диаграммы и таблицы редактируемые.
PPTX и PDF воспроизводят редактор: изображение не закрывает текст, шрифты/цвета/фоны сохранены.
Мобильный редактор 390 px не входит в задачу.

## Готовая основа и зоны работы

Сначала прочитай AGENTS.md и docs/ARCHITECTURE.md. Уже есть independent copy, смысловые группы,
safeChars, серверные снимки и конфликты редактора, native KPI/charts/tables, recovery checkpoints,
новый typed dataset path и контроль принадлежности значений. Не реализуй их повторно.
В этой ветке интегрированы локальные `_composition_geometry.py`, `_apply_safe_text_area`,
сохранение абзацев/маркеров и `checks/image_readability.py`. Проверь качество этих реализаций,
а не считай существующие тесты достаточной приёмкой.

Твоя основная зона: engine/parser, layout, visuals, export, render, checks, API их связки;
packages/pipeline/src/generation/illustrations.ts и ближайший вызов запроса иллюстраций;
registry/agents/illustrator. Контрактное изменение делай минимальным, с Zod и codegen вместе.
Не переписывай оркестрацию, auth, корпоративные квоты, chat discovery и dataset grounding.

## Обязательные исправления

1. Замкни ограничения изображения через весь путь. Сейчас IllustrationRequest.box влияет
   лишь на wide/square/tall; draw не получает области текста, crop и защитные подложки.
   Передай нормализованные области текста относительно кадра, crop, реальные цвета текста,
   доступную защиту и ограничения шаблона. Ключ image task/checkpoint обязан включать значимые
   ограничения. Совместимые потребители переиспользуют изображение, несовместимые не делят
   один результат молча. Не добавляй платный вызов для каждого слайда без необходимости.
   Тесты: одинаковые ограничения → один task; разные text regions/crop/protection → разные
   совместимые решения; реальный provider input содержит ограничения; resume не теряет ключ.
2. Проверь итоговый файл и рендер. У контраста поверх картинки есть состояния measured,
   violation и unknown. Unsupported gradient/theme/transforms не равны pass. Исправляй в рамках
   шаблона или сообщай требует проверки; не выключай аудит и не заливай шаблон чужой плашкой.
3. Проверь измерение safeChars на коротком sample при большой рамке, препятствиях, группах,
   inherited font/indent, bullets и wrap. Не возвращай ограничение длиной образца. Связанные
   heading/body и порядок step сохраняются при смене макета. При неясной семантике remap
   консервативный. Не исправляй дефицит разнообразия потерей фактов.
4. Сделай структурную проверку трёх вариантов: выбор/последовательность композиций, структура
   блоков и размещение информации. Если профиль не позволяет три самостоятельных дизайна,
   выявляй это до дорогих запросов и показывай ограничение. Не принимай три дубликата как успех.
5. Round-trip native объектов: исходные category/series/value/unit/period, null отдельно от 0,
   отрицательные значения, неодинаковый шаг X и пропуски. Проверь PPTX import после export,
   реальные данные диаграммы, таблицы и KPI; не превращай всё в bitmap. Не подменяй значения
   картинкой с красивыми числами и не выдумывай данные для заполнения.
6. Повтори сценарий QA: фон/картинка полного слайда, текст поверх, вложенные группы, сохранённая
   правка редактора, экспорт той же revision в PPTX/PDF. Порядок фигур и наследуемый стиль
   должны пережить экспорт. Сравни картинки редактора и конечного файла.

## Работа и приёмка

Только yarn и uv, проверки через Nx. TS вызывает модели, Python работает с PPTX без моделей;
engine слои не импортируют друг друга, соединение в API. Registry промпты не в коде, смысловая
правка поднимает semver. Нет hardcode имён шаблонов, координат, цветов/шрифтов. Не отключать
lint/types/boundaries. docs/AUDIT.md генерируется. Не коммитить runs, env и датасет организаторов.

Можно максимум два субагента одновременно, каждый на самостоятельный пакет с непересекающимися
файлами: например image constraints и native round-trip. Без рекурсивного делегирования,
повторного общего обзора проекта и микропоручений. Простые проверки отдавай дешёвой модели,
если доступна. Сам держи архитектуру и интеграцию; один сводный раунд исправлений по ревью.
429 не лечить ростом параллельности. Общий generation budget 290 секунд, внешний максимум
300 секунд для трёх готовых вариантов; подготовка отдельно, не скрытое написание слайдов.
Платные live calls — только при предоставленном пользователем бюджете.

Доведи до кода, passing/failing tests каждой проверки, typecheck/lint/boundaries/codegen,
реальных PPTX/PDF на синтетических A/B и третьем неизвестном шаблоне. Сними contact sheets,
открой и оцени их сам. Если LibreOffice/шрифты недоступны, явно оставь этот gate открытым.
В PR укажи исходный SHA, корневые причины, изменения, команды/результаты, ссылки на разрешённые
артефакты и оставшиеся ограничения. Не объявляй SLA или визуальное качество доказанными по unit tests.
