# Совместимость текстовых провайдеров

## Область

Чат и генерация работают с текстовыми моделями через OpenAI-совместимый
`POST /chat/completions`. Поддержка произвольных нативных API и неподходящих
модальностей не подразумевается. Модель и подключение не заменяются автоматически.

## Требования

1. Строгая JSON Schema — предпочтительный, но не обязательный транспорт. При явном
   отказе параметра схемы тот же запрос повторяется в `json_object`, затем без
   `response_format`, если JSON-режим тоже явно отклонён. Исходная схема остаётся
   в контексте и локальной Zod-валидации; словари не теряют ключи или значения.
2. Неподдерживаемые `seed`, `temperature`, `top_p` удаляются только после явного
   отказа соответствующего параметра; `max_tokens` заменяется на
   `max_completion_tokens` с сохранением лимита. Пользовательские thinking/effort
   нельзя молча отбрасывать. Нельзя изменять модель, содержимое задания или ключи.
3. Нестандартный поток без индекса вызова инструмента или финального `[DONE]`
   не разрешает выполнение инструментов. Для чисто завершившегося транспорта допускается один повтор без streaming;
   предварительный текст заменяется проверенным ответом без дублирования. Только
   новый полный ответ с корректной причиной завершения может разрешить действие.
   Настоящий обрыв, повреждённый JSON и усечённые ответы не принимаются.
4. Отказ streaming до начала ответа позволяет запросить полный ответ.
5. Перегрузка, отсутствие авторизации и произвольные HTTP 400 не запускают
   согласование возможностей. Перегрузка и сетевые повторы сохраняют свои бюджеты;
   согласование ограничено числом шагов и общим deadline запроса.
6. Согласованные особенности запоминаются только внутри адаптера одного
   подключения, не смешиваются между моделями, ключами и пользователями.
7. Ошибка сообщает HTTP status и безопасное имя отклонённого параметра, не
   произвольный текст провайдера и не секреты. Ошибка протокола не выдаётся за
   физическую недоступность модели.

## Приёмка

Офлайн-тесты покрывают строгий/JSON/текстовый режимы, сохранение словарей, исходную
валидацию, нестандартный Qwen-поток, buffered retry, реальный обрыв, усечение,
неподдерживаемые параметры, отсутствие скрытой смены модели и bounded retries.
Реальные контрольные вызовы Qwen и GPT проверяются отдельно от тестов с фейковым
провайдером. Успешный HTTP сам по себе не считается успешной генерацией: ответ
обязан пройти исходный контракт.
